# RiChangPIM v1.9.5 Version Log

Release date: 2026-10-27

## Release Scope

This release delivers the AI Configuration Centre — a single admin-only page under `AI 功能` that manages the third-party AI provider settings used by both product-attribute retrieval (选品检索/知识库) and the content workshop — together with a content-quality pass on the content workshop and the standalone topic module, and the enrichment of the product facts that feed those prompts. It also fixes the permission seed migration and hardens the SPA cache policy.

## Main Changes

- **AI 配置中心 (`AI 功能 → AI 配置中心`, admin only)**: new `ai_provider_config` table (migration `0031_ai_provider_config`) and `ai:config` permission code. Two scopes — `knowledge` (main AI: selection retrieval, knowledge base, polish/recommend) and `content` (content workshop / topics) — each configurable for API URL, API key, chat model ID, selectable model list, embedding model and timeout. Resolution is a per-field DB override with env fallback: a blank field falls back to the environment variable, and disabling a scope falls back for the whole scope. Effective within ~15 s across all workers with no restart. Reads return masked keys only; `POST /ai/config/{scope}/test` performs a minimal connectivity probe (10 s, no retry, upstream body never returned).
- **Content generation quality**: both DNA content Skills and the standalone topic prompts were rewritten so writing rules come first and fact/compliance rules are stated as back-stage-only constraints; the disclaimer and verification wording must never appear in `title`/`body`/`hashtags`. The generation-side system message is now a writer persona, with compliance still enforced by the post-guard and `verification_gaps`. Product facts grew from 3 to 12 fields (category, brand, material, material description, colours, description, governed attributes); only trusted attribute sources are used and `ai_inferred` unverified values are dropped. Price, stock and supplier fields never reach an external prompt.
- **Skill seed `--refresh` mode**: refreshes already-existing operational Skills in place from the code templates (the previous mode only skipped existing rows).
- **Migration fix**: `0031_ai_provider_config` inserted into `permission` using non-existent columns (`code`/`name`); corrected to `perm_code`/`perm_name`, matching the real table and `0020_crm_perms`.
- **SPA cache policy**: nginx previously sent no `Cache-Control` at all. Entry HTML is now `no-cache` (always revalidated) and content-hashed assets under `/admin/assets/` and `/assets/` are `public, max-age=31536000, immutable`. This removes the post-deploy white screen where a browser holding a stale `index.html` requested chunk names that no longer exist.
- **API response contract fix**: the AI config frontend read one envelope level too deep (`resp.data.data`) and always rendered an empty page.

## Compatibility and Upgrade Notes

- The configuration table is an override layer: after upgrading, leaving every field empty reproduces v1.9.4 behaviour exactly. No configuration is required.
- Migration head moves from `0030_content_dna_fields` to `0031_ai_provider_config`.
- The `ai:config` permission is granted only through `admin`'s `*`; no other role receives it.
- Existing sessions keep working; no re-login is required.
- `scripts/seed_default_skills --refresh --check` previews which operational Skill fields the code templates would overwrite before `--refresh --apply`.

## Package Boundary

- Full migration bundle: `RiChangPIM_v1.9.5_<ts>.tar.gz` — source, configuration, PostgreSQL, MinIO and optional Redis state for rebuilding the whole stack on a clean host.
- Cloud update package: `RiChangPIM_update_v1.9.5_<ts>.tar.gz` — source, configuration templates, migrations and build scripts only; no business data, object storage, `.env` or credentials.
