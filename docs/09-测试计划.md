## 二、接口契约测试

### 2.1 测试范围

每个 API 端点必须覆盖以下场景：

| 场景 | 说明 |
| --- | --- |
| 正常请求 | 合法参数，验证响应结构与状态码 |
| 参数缺失 | 必填参数缺失，返回 40001 |
| 参数非法 | 类型/格式错误，返回 40002 |
| 未认证 | 无 Token，返回 40101 |
| Token 过期 | 返回 40102 |
| 无权限 | 角色无权访问，返回 40301 |
| 资源不存在 | 返回 40401 |
| 资源冲突 | 唯一约束冲突，返回 40901 |

### 2.2 测试示例（产品检索接口）

```python
import pytest
from httpx import AsyncClient

class TestProductAPI:
    async def test_list_products_success(self, client: AsyncClient, auth_token):
        resp = await client.get(
            "/api/v1/products?category_id=12&page=1&size=20",
            headers={"Authorization": f"Bearer {auth_token}"}
        )
        assert resp.status_code == 200
        data = resp.json()
        assert data["code"] == 200
        assert "list" in data["data"]
        assert "total" in data["data"]

    async def test_list_products_no_auth(self, client: AsyncClient):
        resp = await client.get("/api/v1/products")
        assert resp.json()["code"] == 40101

    async def test_list_products_sales_no_cost_price(self, client: AsyncClient, sales_token):
        resp = await client.get(
            "/api/v1/products",
            headers={"Authorization": f"Bearer {sales_token}"}
        )
        products = resp.json()["data"]["list"]
        assert all("cost_price" not in p for p in products)
```

## 三、AI Adapter 回归测试

### 3.1 测试目标

确保 `AIServiceAdapter` 各实现类（FastGPT/Dify/RagFlow）返回结构一致，切换引擎不影响业务层。

### 3.2 测试范围

| 测试项 | 说明 |
| --- | --- |
| 接口契约一致性 | `chat()` 返回结构包含 `answer`/`sources`/`tool_calls` |
| 流式输出一致性 | `chat_stream()` 输出帧类型与格式统一 |
| Tool Call 解析 | `parse_tool_calls()` 抹平各引擎差异 |
| 会话管理 | `manage_session()` 创建/拉取/删除一致 |
| 错误隔离 | 下游引擎异常统一转为 50201 |
| 超时控制 | 下游超时不阻塞业务 |
| 引擎切换 | 切换 `AI_ADAPTER` 配置后业务层行为不变 |

### 3.3 测试示例

```python
import pytest
from app.adapters import get_adapter

class TestAIAdapterContract:
    @pytest.mark.parametrize("adapter_name", ["fastgpt", "dify", "ragflow"])
    async def test_chat_returns_unified_structure(self, adapter_name):
        adapter = get_adapter(adapter_name)
        result = await adapter.chat(
            session_id="test_session",
            message="推荐会议室投影设备",
            history=[]
        )
        assert "answer" in result
        assert "sources" in result
        assert isinstance(result["sources"], list)

    @pytest.mark.parametrize("adapter_name", ["fastgpt", "dify", "ragflow"])
    async def test_parse_tool_calls_format(self, adapter_name):
        adapter = get_adapter(adapter_name)
        raw = adapter._mock_raw_response()
        tool_calls = adapter.parse_tool_calls(raw)
        assert all("target_api" in tc for tc in tool_calls)
        assert all("parsed_arguments" in tc for tc in tool_calls)
```

### 3.4 回查闭环测试

```python
class TestCallbackLoop:
    async def test_vector_recall_not_final_output(self, ai_service):
        """向量召回结果不能直接作为最终数据输出"""
        result = await ai_service.recommend("预算5万的投影设备")
        # 验证价格字段来自 Business API 回查，而非 AI 直接输出

    async def test_strong_fields_verified(self, ai_service):

        result = await ai_service.recommend("查库存")
        for product in result["products"]:
            assert "price" in product
            assert "stock_status" in product
            assert product["_verified"] is True
```

## 四、字段级权限自动化测试

### 4.1 测试目标

确保敏感字段（`cost_price`、`supplier_id`、`customer_contact`）在不同角色下的可见性正确。

### 4.2 权限矩阵测试

```python
class TestFieldPermission:

    async def test_sales_cannot_see_supplier_id(self, client, sales_token):

        )
```

## 五、端到端流程测试

### 5.1 核心链路 E2E

| 链路 | 测试步骤 | 验证点 |
| --- | --- | --- |
| 产品录入 → 方案 → 分享 | 上传产品 → 生成方案 → 分享 → 扫码查阅 | 全链路打通，权限正确 |
| AI 推荐回查 | 输入模糊需求 → AI 推理 → Business API 回查 → 结果呈现 | 回查闭环生效 |
| 字段权限隔离 | 销售查看产品 → 采购查看产品 | 成本价可见性差异 |
| 分享安全 | 生成分享 → 密码访问 → 过期访问 → 超次访问 | 访问控制正确拦截 |

### 5.2 Playwright 示例

```javascript
// e2e/product-to-share.spec.ts
test('产品录入到分享全链路', async ({ page }) => {
  // 1. 管理员登录，录入产品
  await page.goto('/login');
  await login(page, 'admin', 'admin123');
  await page.goto('/products/new');
  await fillProductForm(page, { name: '测试产品A', price: 1000 });
  await page.click('button:has-text("上架")');

  // 2. 切换销售账号，生成方案
  await login(page, 'sales', 'sales123');
  await page.goto('/products');
  await page.check('input[data-product="测试产品A"]');
  await page.click('button:has-text("生成方案")');

  // 3. 分享并扫码
  await page.click('button:has-text("分享")');
  const shareUrl = await page.getAttribute('[data-share-url]', 'href');

  // 4. 无痕窗口访问分享页
  const context = page.context();
  const newPage = await context.newPage();
  await newPage.goto(shareUrl);
  await expect(newPage.locator('h1')).toContainText('测试产品A');
});
```

## 六、性能测试

### 6.1 关键接口压测目标

| 接口 | 场景 | 目标 QPS | P99 延迟 |
| --- | --- | --- | --- |
| GET /products | 列表查询 | 100 | < 200ms |
| POST /ai/chat | AI 对话（非流式） | 10 | < 5s |
| POST /ai/chat (stream) | AI 流式对话 | 10 | 首 token < 1s |
| POST /shares | 生成分享 | 50 | < 300ms |
| GET /share/{token} | 分享页访问 | 200 | < 100ms |

### 6.2 Locust 示例

```python
from locust import HttpUser, task, between

class PIMUser(HttpUser):
    wait_time = between(1, 3)

    @task(3)
    def list_products(self):
        self.client.get("/api/v1/products", headers=self.auth_headers)

    @task(1)
    def ai_chat(self):
        self.client.post("/api/v1/ai/chat", json={
            "question": "推荐会议室投影设备",
            "stream": False
        }, headers=self.auth_headers)
```

### 6.3 并发与事务测试

| 测试项 | 说明 | 预期 |
| --- | --- | --- |
| ShareToken 并发访问 | 10 并发同时访问次数将满的 token | 不超额，计数准确 |
| 产品库存并发更新 | 2 用户同时修改同一产品 stock_status | 乐观锁生效，后操作者重试或失败 |
| 产品双写事务 | 向量化失败时 | 业务数据回滚，无脏数据 |
| 分享撤销级联 | 撤销分享后 10 个并发访问 | 全部拒绝，token 已失效 |
| JWT refresh 并发 | 同一 refresh_token 并发刷新 | 仅一次成功，旧 token 失效 |

## 八、P2 执行门禁

### 8.1 后端测试入口

```bash
cd backend
PYTHONPATH=. pytest
```

执行约束：

- 纯单元测试不依赖数据库。
- DB 集成测试只在 `TEST_DATABASE_URL` 可达且目标库安全时运行。
- 目标库名必须包含 `test`，否则必须显式设置 `AI_PIM_TEST_DB_APPROVED=1`。
- `pgvector` 依赖缺失时测试应直接失败，不能静默退回普通 SQLAlchemy 列类型。

### 8.2 本地测试数据库

项目基线数据库为 PostgreSQL 16 + pgvector，使用仓库现有开发编排启动：

```bash
docker compose -f docker-compose.dev.yml up -d postgres redis minio
```

`docker/postgres/initdb/01-create-test-db.sql` 会在数据目录首次初始化时创建 `ai_pim_test`。随后运行：

```bash
cd backend
TEST_DATABASE_URL=postgresql+asyncpg://pim:${POSTGRES_PASSWORD:-pim_password}@localhost:5432/ai_pim_test \
PYTHONPATH=. pytest
```
