## 二、MVP - 核心打通

### 2.1 目标

打通 **"产品录入 → 方案生成 → H5 分享"** 核心销售链路，优先验证业务价值。

> ⚠ RAG 说明书问答从 MVP 移到 V1，避免范围过大影响交付质量。

### 2.2 功能范围

| 模块 | 交付内容 |
| --- | --- |
| 用户与权限 | 用户管理、RBAC 基础权限（菜单/按钮/接口） |
| 产品中心 | 产品 CRUD、分类管理、Excel 导入导出、标签管理 |
| 供应商 | 基础 CRUD |
| 品牌 | 基础 CRUD |
| 文件中心 | 文件上传、MinIO 存储 |
| 方案中心 | 勾选产品生成方案、基础明细 |
| 分享中心 | H5 分享 + 二维码 + 公开/关闭 |

### 2.3 验收标准

1. 管理员可完成产品录入、分类管理、Excel 批量导入
2. 销售可勾选产品生成方案并查看明细
3. 销售可生成分享链接与二维码，客户扫码可查阅 H5 方案
4. 基础 RBAC 权限生效（销售/管理员角色隔离）
5. Docker Compose 一键部署启动

### 2.4 建议周期

4-6 周

### 2.5 MVP 交付物清单

| 交付物 | 说明 | 负责方 |
| --- | --- | --- |
| 后端代码 | FastAPI + Alembic 迁移脚本 | 后端 |
| 前端代码 | Vue3 构建 + 19 个页面 | 前端 |
| OpenAPI JSON | FastAPI 自动生成 /openapi.json | 后端 |
| Postman Collection | 基于 OpenAPI 生成，供前端联调 | 后端 |
| API Mock | 基于OpenAPI的Mock服务（如Apifox/Mock.js） | 后端 |
| Docker Compose 部署脚本 | 含 docker-compose.yml + .env.example | 运维 |
| 数据库初始化脚本 | Alembic 迁移 + 种子数据 | 后端 |
| 用户手册 | 管理员/销售操作指南 | 产品 |
| 部署文档 | 06-部署方案.md | 运维 |

## 三、V1 - 效能起飞

### 3.1 目标

引入 AI 能力，实现智能推荐与方案润色，补全报价与分享安全能力。

### 3.2 功能范围

| 模块 | 交付内容 |
| --- | --- |
| AI 能力中心 | AIServiceAdapter 抽象层 + 首个引擎接入（FastGPT/Dify/RagFlow 三选一） |
| 文档知识检索（RAG） | 产品说明书解析、技术参数问答 |
| 产品智能推荐 | 模糊需求 → 意图拆解 → Business API 查询 → 回查闭环 |
| AI 方案润色 | 亮点提炼、行业话术、推荐理由生成 |
| 报价中心 | 动态报价单、税率/折扣、Gotenberg PDF 导出 |
| 分享安全 | 密码保护、到期失效、限制访问次数、ShareToken 表 |
| 字段级权限 | 敏感字段响应层过滤（cost_price/supplier_id） |
| 数据统计 | 产品统计、方案/报价汇总、分享访问看板 |
| OCR 解析 | MinerU 自动解析 PDF 说明书 |
| 操作审计 | OperationLog 系统操作日志 |

### 3.3 验收标准

1. AI 推荐可正确理解模糊需求并转化为标准筛选条件
2. 回查闭环生效：AI 不直接输出价格/库存，由 Business API 回查确认
3. 方案可 AI 润色并生成推荐理由
4. 报价单可动态调价并导出高保真 PDF
5. 分享链接支持密码/到期/次数限制
6. 字段级权限：销售无法查看成本价
7. 切换 AI 引擎（适配器）业务层零改造

### 3.4 建议周期

6-8 周

## 四、V2 - 企业集成

### 4.1 目标

与企业现有系统集成，支持多租户 SaaS 化。

### 4.2 功能范围

| 模块 | 交付内容 |
| --- | --- |
| 企微/钉钉打通 | 组织架构同步、消息通知、单点登录 |
| CRM/ERP 接口对接 | 产品/客户数据同步（标准 REST API） |
| 多租户隔离 | tenant_id 分区、租户级数据隔离 |
| 审批流引擎 | 方案/报价审批流程集成 |
| AI 营销文案 | 小红书/朋友圈/SEO/短视频脚本生成 |
| AI 培训助手 | 产品竞争优势问答、销售话术培训 |

### 4.3 验收标准

1. 企微/钉钉组织架构可同步，支持单点登录
2. 多租户数据严格隔离，租户间不可交叉访问
3. 审批流可配置化，支持多级审批
4. K8s 部署支持 API 水平扩展

### 4.4 建议周期

8-10 周

## 六、实施补充建议

以下关键约束建议在各阶段实施过程中严格落实：

1. **AI Adapter 接口契约**：尽早定义 `AIServiceAdapter` 统一接口，避免后续接入新引擎时反复改造业务层
2. **字段级权限双重防线**：查询层 + 响应序列化层双重兜底，避免权限漏检
3. **主键与数据治理**：统一 UUID v7 主键 + 软删除规范（`deleted_at` + `is_deleted`）
4. **分享凭证治理**：ShareToken 表独立收敛，便于权限审计与扩展
5. **MVP 收敛**：始终聚焦"产品录入 → 方案生成 → H5 分享"核心链路
6. **测试补档**：每个阶段配套接口契约测试、AI Adapter 回归测试、字段权限测试

## 八、Plan D 实施要点（V1 AI 能力中心）

### D1 — OpenAI 适配层

- `AIServiceAdapter` 抽象接口 + `OpenAIAdapter` 实现 + `NoneAdapter` 兜底
- Factory 模式按环境变量切换引擎（`AI_ENGINE=none/openai/fastgpt/dify/ragflow`）
- Embedding 维度统一 1536（与 OpenAI text-embedding-3-small 对齐）

### D2 — RAG 文档切片检索

- 切片策略：600 字符/片，重叠 80 字符（中文估算）
- HNSW 索引 + cosine 相似度，`top_k=8`，`min_score=0.65` 剔除噪声
- `product_manual_chunk` 表存储切片，关联 `product_manual` 与 `product`

### D3 — 润色与选品

- `proposal.ai_polish_content` / `ai_polish_at` / `ai_polish_model` 记录 LLM 输出
- 智能选品：模糊需求 → 意图拆解 → Business API 回查
- `cost_price` 由 sales 路径 serializer 兜底过滤（双重防线）

> 后续：M3 V2 多租户/企微集成需先打好 smoke e2e 测试基线。
