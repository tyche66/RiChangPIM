# P0 试点产品数据治理方案

> 状态：P0 数据门文档。当前试点数据来自 `backend/data/sunon_pilot_products.json`，共 13 条圣奥办公家具产品，均存在 `status=draft`、`completeness_status=pending`、`face_price=99999`、`cost_price=null`、`stock_status=unknown` 等占位问题。

## 1. 试点数据可验证场景

P0 试点数据只能支持有限验证，不得扩大宣传：

| 场景 | 可验证程度 | 说明 |
| --- | --- | --- |
| 按风格/场景/材质/规格找产品 | 可验证 | 产品名称、描述、材质、颜色、规格相对可用 |
| 精确产品/型号识别 | 可验证 | 可用产品编号、名称、类目做规则识别 |
| 基础多产品比较 | 部分可验证 | 仅比较已有结构化字段和说明文字 |
| 说明书问答 | 依赖附件 | 需要补齐说明书、规格书、证书和页码来源 |
| 数据治理助手 | 可验证 | 可查询待核价、库存未知、缺资料、draft 状态 |
| 采购辅助 | 仅可验证权限与缺口表达 | 缺成本、供应商质量、交期、库存流水，不可做实际采购建议 |

## 2. 禁止宣称能力

- 不宣称实时价格。
- 不宣称实时库存或库存预测。
- 不宣称自动采购、自动补货、自动下单。
- 不宣称客户画像、成交预测、基于购买历史个性化推荐。
- 不宣称自动发送分享、自动确认报价、自动修改产品状态。
- 不把 `99999` 展示为真实价格。

## 3. 关键状态规则

| 数据状态 | AI 与 Portal 展示规则 | 工程要求 |
| --- | --- | --- |
| `face_price=99999` | 显示“待核价” | 不进入模型上下文作为价格事实 |
| `stock_status=unknown` | 显示“库存待确认” | 不推断有货或缺货 |
| `status=draft` | 默认不进入正式销售推荐 | 内部治理/采购查询可见但要标注 draft |
| `completeness_status=pending` | 显示“资料待完善” | 推荐理由降置信度 |
| `cost_price=null` | 对 sales/viewer 不可见 | 采购/管理员也要标注缺失 |

## 4. 数据补齐优先级

| 优先级 | 数据项 | 目标 | 责任建议 |
| --- | --- | --- | --- |
| P0-1 | 基础字段 | 名称、编号、类目、品牌、材质、颜色、规格完整 | 数据管理员 |
| P0-1 | 价格状态 | 确认是否仍待核价；不能确认时继续显示“待核价” | 产品/销售负责人 |
| P0-1 | 说明书附件 | 每个可验证产品至少 1 份说明书/规格书 | 知识数据 Owner |
| P0-2 | 章节页码 | 能打开原文并定位页码/章节 | AI/数据工程 |
| P0-2 | 规格结构化 | 参数名、值、单位、适用型号可比较 | 数据管理员 |
| P0-2 | 图片资料 | 产品卡片封面和场景图齐全 | 运营/设计 |
| P0-3 | 供应商字段 | 仅供采购/管理员权限池验证 | 采购负责人 |
| P0-3 | 质量问题 | 缺图、缺说明书、库存未知、待核价等标签化 | 数据治理负责人 |

## 5. 治理流程

```text
补录基础字段
  -> 业务负责人核验
  -> 上传/替换说明书附件
  -> 解析与索引（Phase 2 Worker 前可手动验证）
  -> 跑 eval/p0/evalset.jsonl 中相关样本
  -> 记录失败原因
  -> 数据修复或标记不支持
  -> 发布前复核
```

任何数据缺口不得交给模型“猜”。模型只能组织表达、总结证据和提出一般建议。价格、库存、供应商、方案、报价状态必须现场查询 PIM 业务字段。

## 6. Portal 联动规则

| UI 组件 | 缺失数据展示 | 禁止行为 |
| --- | --- | --- |
| 产品卡片 | 待核价、库存待确认、资料待完善 | 不显示 99999，不用颜色暗示有货 |
| 比较表 | 单元格显示“资料未提供” | 不让模型补齐缺失参数 |
| 来源卡片 | 区分数据库事实/文档证据/模型推断 | 来源失效后不得继续展示正文 |
| 待确认动作 | 仅显示可验证字段和影响范围 | 不在前端本地视为已执行 |

## 7. 可插拔原则

数据治理不绑定某个检索实现或模型供应商。产品知识卡片、说明书索引、质量规则、评测样本均通过稳定接口进入 Gateway：`ProductFactProvider`、`KnowledgeDocumentProvider`、`QualityRuleProvider`。Phase 1 可先用现有表和同步 RAG，Phase 2 再替换为 Worker/通用知识表，不影响 Portal 契约。

## 8. P0 最小完成条件

- 至少销售选型与知识问答两条链路可重复验证。
- 所有 `99999` 价格在答案和 UI 中显示为“待核价”。
- 所有 `unknown` 库存显示为“库存待确认”。
- draft 产品不进入正式销售推荐。
- 说明书/规格书来源能打开或明确标注缺失。
- 采购辅助只输出数据缺口，不做自动采购建议。
