# 当前部署方案

本文档描述 RiChangPIM 当前 `v1.9.1` 的 Docker Compose 部署和本地开发方式。历史概念方案已归档至 [`过时/`](./过时/)。实机运维、备份和故障恢复以 [`../README-OPS.md`](../README-OPS.md) 为准。

## 生产 Compose

生产编排文件为 [`../docker-compose.yml`](../docker-compose.yml)，当前服务为：

| 服务 | 作用 | 持久化 | 对外端口 |
| --- | --- | --- | --- |
| `nginx` | Portal、Admin、API 统一入口 | cert bind mount | `888:80` |
| `backend` | FastAPI Business API | backups 只读挂载 | Compose 内 8000 |
| `postgres` | PostgreSQL 16 + pgvector | 命名卷 | 不发布 |
| `redis` | 缓存、限流和 token 黑名单 | 命名卷 | 不发布 |
| `minio` | 产品媒体和附件 | 命名卷 | 不发布 |
| `gotenberg` | PDF 转换 | 无业务卷 | 不发布 |
| `ocr` | OCR 服务，默认可关闭 | 无业务卷 | 不发布 |

生产首次部署：

```bash
cp .env.example .env
# 填写 POSTGRES_PASSWORD、JWT_SECRET、ADMIN_PASSWORD、MINIO_ROOT_* 等真实值
export PATH="$HOME/.nvm/versions/node/v24.18.0/bin:$PATH"
bash scripts/build_frontends.sh
docker compose up -d
```

backend 容器启动时自动执行数据库迁移、管理员初始化和种子数据。前端或 nginx 配置变更后必须重建 nginx 镜像：

```bash
bash scripts/build_frontends.sh
docker compose build nginx
docker compose up -d --no-deps nginx
```

后端源码变更后重建 backend。发布前必须从 [`README-OPS.md`](../README-OPS.md) 的 runbook 导出同一组版本元数据。

## 入口与网络

- 当前实机入口：`http://127.0.0.1:888/`
- 管理后台：`http://127.0.0.1:888/admin/`
- API：`http://127.0.0.1:888/api/v1/`
- 容器内部 backend：`http://backend:8000`
- 生产 PostgreSQL、Redis、MinIO、Gotenberg、OCR 均只在 Compose 网络内访问。
- 当前实机没有可用的宿主机 `:8000`、`:5432`、`:9000` 或 `:9001` 生产入口。

正式公网部署应由上游 TLS 终止层提供 HTTPS；本地 `888:80` 是当前实机验收入口，不应据此推断生产一定发布 443。

## 本地开发

```bash
docker compose -f docker-compose.dev.yml up -d
cd backend
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Admin 和 Portal 分别在 `frontend/`、`portal/` 运行 Vite。开发 Compose 发布 PostgreSQL `5432`、Redis `6379`、MinIO `9000/9001` 和 Gotenberg `8002`，数据目录默认在 `docker/volumes/`。
