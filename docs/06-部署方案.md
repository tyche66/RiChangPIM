# 06 - 部署方案

> 本文档基于概念方案技术栈选型，提供 Docker Compose 私有化部署指南与 K8s 集群部署演进方向。

> ⚠️ **这是方案文档，不是实机现状。** 本机（2026-07-31 实测）与下文有四处已知偏差，
> 照本文档操作会踩坑。实机为准的文档是 [../README-OPS.md](../README-OPS.md) 和 `/home/AI-PIM/从启动到穿透.md`：
>
> 1. **Nginx 对外端口是 `888:80`**，没有 `443`（本地自签证书只用于验收）。生产入口是 `http://127.0.0.1:888/`。
> 2. **`frontend/dist` / `portal/dist` 不是 bind mount，是 build 时 `COPY` 进 nginx 镜像的。**
>    只在宿主机 build 不会改变 `:888`，必须 `docker compose build nginx && docker compose up -d --no-deps nginx`。
> 3. **backend 的 `8000:8000` 在本机没有生效**（Windows 有系统进程占着 `0.0.0.0:8000`），
>    后端只能经 nginx `:888` 访问；postgres / redis / minio 都没有发布端口。
> 4. 前端构建入口是 `bash scripts/build_frontends.sh`（含版本注入 + 后台按 `VITE_BASE_PATH=/admin/` 构建），
>    不是裸 `npm run build`；backend 侧的版本元数据要按 README-OPS「升级发布 runbook」第 3 步手工 export，
>    否则 compose 默认值会让后端自报 `dev`。

## 一、部署架构总览

### 1.1 组件清单

| 组件 | 镜像/技术 | 端口 | 说明 |
| --- | --- | --- | --- |
| Nginx | nginx:alpine | 80/443 | 反向代理 + HTTPS 终止 |
| Portal | Vue3 构建产物（静态） | - | 内部 AI 前台，由 Nginx 托管到 `/` |
| Admin | Vue3 构建产物（静态） | - | 现有管理后台，由 Nginx 托管到 `/admin/` |
| 后端 API | FastAPI (Python) | 8000 | Business API 核心服务 |
| PostgreSQL | postgres:16 + pgvector | 5432 | 业务数据 + 向量存储 |
| Redis | redis:7-alpine | 6379 | 缓存 + 限流 |
| MinIO | minio/minio | 9000/9001 | 私有化对象存储 |
| MinerU | OCR 服务 | 8001 | PDF 解析（V1 启用） |
| Gotenberg | gotenberg/gotenberg | 8002 | HTML → PDF 渲染 |
| AI 引擎 | FastGPT / Dify / RagFlow | 8003+ | 可插拔 AI 引擎 |

## 二、Docker Compose 部署（MVP 推荐）

### 2.1 目录结构

```
ai-pim/
├── docker-compose.yml
├── .env
├── nginx/
│   ├── nginx.conf
│   └── certs/
├── backend/
│   ├── Dockerfile
│   ├── requirements.txt
│   └── app/
├── frontend/
│   ├── Dockerfile
│   └── dist/
└── sql/
    └── init.sql
```

### 2.2 docker-compose.yml

```yaml
version: "3.8"

services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf
      - ./nginx/certs:/etc/nginx/certs
      - ./portal/dist:/usr/share/nginx/portal
      - ./frontend/dist:/usr/share/nginx/admin
    depends_on:
      - backend
    restart: always

  backend:
    build: ./backend
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=postgresql://pim:pim_password@postgres:5432/ai_pim
      - REDIS_URL=redis://redis:6379/0
      - MINIO_ENDPOINT=minio:9000
      - MINIO_ACCESS_KEY=pim_minio
      - MINIO_SECRET_KEY=pim_minio_secret
      - JWT_SECRET=your_jwt_secret_here
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_started
    restart: always

  postgres:
    image: pgvector/pgvector:pg16
    ports:
      - "5432:5432"
    environment:
      - POSTGRES_USER=pim
      - POSTGRES_PASSWORD=pim_password
      - POSTGRES_DB=ai_pim
    volumes:
      - pg_data:/var/lib/postgresql/data
      - ./sql/init.sql:/docker-entrypoint-initdb.d/init.sql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U pim"]
      interval: 10s
      timeout: 5s
      retries: 5
    restart: always

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data
    restart: always

  minio:
    image: minio/minio
    ports:
      - "9000:9000"
      - "9001:9001"
    environment:
      - MINIO_ROOT_USER=pim_minio
      - MINIO_ROOT_PASSWORD=pim_minio_secret
    command: server /data --console-address ":9001"
    volumes:
      - minio_data:/data
    restart: always

  gotenberg:
    image: gotenberg/gotenberg:8
    ports:
      - "8002:3000"
    restart: always

volumes:
  pg_data:
  redis_data:
  minio_data:
```

### 2.3 环境变量（.env）

```env
# 数据库
POSTGRES_USER=pim
POSTGRES_PASSWORD=pim_password
POSTGRES_DB=ai_pim

# JWT

JWT_EXPIRE_HOURS=2

# MinIO

MINIO_ROOT_PASSWORD=pim_minio_secret

# AI 引擎（按实际接入配置）
AI_ADAPTER=fastgpt
FASTGPT_API_URL=http://fastgpt:3000
FASTGPT_API_KEY=your_fastgpt_key
```

### 2.4 Nginx 配置要点

```nginx
server {
    listen 443 ssl;
    server_name pim.example.com;

    ssl_certificate     /etc/nginx/certs/server.crt;
    ssl_certificate_key /etc/nginx/certs/server.key;

    # Portal
    location / {
        root /usr/share/nginx/portal;
        try_files $uri $uri/ /index.html;
    }

    # Admin
    location /admin/ {
        alias /usr/share/nginx/admin/;
        try_files $uri $uri/ /admin/index.html;
    }

    # API 反向代理
    location /api/ {
        proxy_pass http://backend:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # SSE 流式支持（AI 对话 / Knowledge Gateway）
    location /api/v1/knowledge/query {
        proxy_pass http://backend:8000;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Authorization $http_authorization;
        proxy_buffering off;          # 关键：关闭缓冲支持流式
        proxy_read_timeout 300s;
    }

    # 分享页 H5
    location /share/ {
        proxy_pass http://backend:8000;
    }
}
```

### 2.5 本地开发环境

开发阶段建议采用"前端热更新 + 后端热重载 + 数据库容器化"的混合模式，避免每次代码改动都重新构建镜像。

#### 开发环境架构

```
开发者本机
├── frontend/  → npm run dev (Vite 热更新, 端口 5173)
├── backend/   → uvicorn main:app --reload (端口 8000)
└── docker-compose.dev.yml  → 仅启动依赖中间件
    ├── postgres (5432)
    ├── redis (6379)
    ├── minio (9000/9001)
    └── gotenberg (8002)
```

#### docker-compose.dev.yml

```yaml
version: "3.8"
services:
  postgres:
    image: pgvector/pgvector:pg16
    ports: ["5432:5432"]
    environment:
      POSTGRES_USER: pim
      POSTGRES_PASSWORD: pim_password
      POSTGRES_DB: ai_pim
    volumes:
      - pg_dev_data:/var/lib/postgresql/data
  redis:
    image: redis:7-alpine
    ports: ["6379:6379"]
  minio:
    image: minio/minio
    ports: ["9000:9000", "9001:9001"]
    environment:
      MINIO_ROOT_USER: pim_minio
      MINIO_ROOT_PASSWORD: pim_minio_secret
    command: server /data --console-address ":9001"
    volumes:
      - minio_dev_data:/data
  gotenberg:
    image: gotenberg/gotenberg:8
    ports: ["8002:3000"]
volumes:
  pg_dev_data:
  minio_dev_data:
```

#### 开发起步步骤

```bash
# 1. 启动依赖中间件
docker-compose -f docker-compose.dev.yml up -d

# 2. 后端
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

# 3. 前端
cd frontend
npm install
npm run dev  # 默认 5173 端口

# 4. 数据库迁移
alembic upgrade head

# 5. 初始化管理员
python -m app.scripts.init_admin
```

#### 前后端联调

- 前端 Vite 配置代理：`/api` → `http://localhost:8000`
- 后端 CORS 允许 `http://localhost:5173`
- 数据库 GUI 推荐 DBeaver / pgAdmin

## 三、数据库初始化

### 3.1 init.sql

```sql
-- 启用 pgvector 扩展
CREATE EXTENSION IF NOT EXISTS vector;

-- 启用 UUID 生成（PostgreSQL 18+ 原生支持 UUIDv7，16 需扩展）
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- 软删除触发器模板（update_time 自动更新）
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.update_time = now();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

## 四、部署步骤

### 4.1 首次部署

```bash
# 1. 克隆代码
git clone <repo-url> ai-pim && cd ai-pim

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env 修改密码与密钥

# 3. 构建前端
cd frontend && npm install && npm run build && cd ..

# 4. 启动全部服务
docker-compose up -d

# 5. 初始化数据库（表结构迁移）
docker-compose exec backend python -m alembic upgrade head

# 6. 创建初始管理员
docker-compose exec backend python -m app.scripts.init_admin

# 7. 验证
curl https://localhost/api/v1/health
```

### 4.2 更新部署

```bash
# 拉取最新代码
git pull origin main

# 重新构建后端
docker-compose build backend

# 滚动更新
docker-compose up -d backend

# 执行数据库迁移
docker-compose exec backend python -m alembic upgrade head
```

## 五、K8s 集群部署演进方向（V2+）

### 5.1 适用场景

- 多租户 SaaS 化部署
- 高可用与弹性伸缩需求
- 多环境（dev/staging/prod）管理

### 5.2 资源规划建议

| 组件 | 资源建议 | 副本数 | 说明 |
| --- | --- | --- | --- |
| API | 1C2G ~ 2C4G | 2+ | 可水平扩展 |
| PostgreSQL | 2C4G+ | 1（主从） | 数据持久化，建议云托管 |
| Redis | 1C1G | 1+ | 可哨兵集群 |
| MinIO | 2C4G+ | 1+（分布式） | 按存储量规划 |
| AI 引擎 | 4C8G+ | 1+ | 按并发量规划 |

### 5.3 关键配置

- API 服务配置 HPA（水平 Pod 自动伸缩）
- PostgreSQL 使用 StatefulSet + 持久卷
- 配置 Ingress 替代 Nginx（支持 TLS 自动续签）
- 敏感配置使用 K8s Secret 管理

## 六、安全加固清单

| 项目 | 措施 |
| --- | --- |
| HTTPS | 全站强制，Nginx 终止 TLS |
| 密码存储 | bcrypt 加密，禁止明文 |
| JWT 密钥 | 使用强随机密钥，定期轮换 |
| 数据库密码 | .env 不提交 Git，使用 Secret 管理 |
| MinIO | 私有 bucket，预签名 URL 访问 |
| 限流 | Redis 令牌桶，AI 接口 10 次/分钟/用户 |
| 防火墙 | 仅暴露 80/443，内部组件内网通信 |

## 七、备份与恢复

| 数据 | 备份方式 | 频率 | 保留 |
| --- | --- | --- | --- |
| PostgreSQL | `pg_dump` 全量 + WAL 归档 | 每日 | 30 天 |
| MinIO 文件 | `mc mirror` 同步至备份存储 | 每日 | 30 天 |
| 配置文件 | Git 版本管理 | 实时 | 永久 |

```bash
# PostgreSQL 备份示例
docker-compose exec postgres pg_dump -U pim ai_pim | gzip > backup_$(date +%Y%m%d).sql.gz

# 恢复
gunzip -c backup_20260712.sql.gz | docker-compose exec -T postgres psql -U pim ai_pim
```

### 7.4 数据保留策略

| 数据类型 | 表 | 保留期 | 清理方式 | 说明 |
| --- | --- | --- | --- | --- |
| 分享访问日志 | share_log | 180 天 | 定时任务 DELETE | 访问审计，半年足够 |
| 系统操作日志 | operation_log | 365 天 | 定时任务 DELETE | 合规审计需要1年 |
| AI 对话记录 | ai_conversation | 90 天 | 定时任务 DELETE | 对话上下文，3个月足够 |
| 访客记录 | visitor | 永久 | 不清理 | 分析型数据，量小 |
| 业务数据 | product/proposal/quotation 等 | 永久（软删除） | 不物理删除 | 软删除保留追溯 |
| 文件对象 | MinIO 对象 | 随业务数据 | 软删除后30天清理 MinIO 孤儿对象 | 定时扫描清理 |

清理任务实现：通过 pg_cron 或应用层定时任务（APScheduler）每日凌晨执行。
