# 07 - 开发规范

> 本文档定义 AI-PIM 项目的代码规范、目录结构、Git 工作流与工程约定。

---

## 一、项目目录结构

### 1.1 仓库结构（单仓多模块）

```
ai-pim/
├── docs/                       # 工程文档体系
├── frontend/                   # Vue3 前端
│   ├── src/
│   │   ├── api/                # API 请求封装
│   │   ├── components/         # 公共组件
│   │   ├── views/              # 页面视图
│   │   ├── router/             # 路由
│   │   ├── store/              # Pinia 状态管理
│   │   └── utils/              # 工具函数
│   ├── package.json
│   └── vite.config.ts
├── backend/                    # FastAPI 后端
│   ├── app/
│   │   ├── api/                # 路由层（接口定义）
│   │   │   └── v1/
│   │   ├── core/               # 核心配置（JWT/权限/中间件）
│   │   ├── models/             # ORM 模型
│   │   ├── schemas/            # Pydantic 请求/响应模型
│   │   ├── services/           # 业务逻辑层
│   │   ├── adapters/           # AI Service Adapter 实现
│   │   │   ├── base.py         # AIServiceAdapter 抽象基类
│   │   │   ├── fastgpt.py      # FastGPT 适配器
│   │   │   ├── dify.py         # Dify 适配器
│   │   │   └── ragflow.py      # RagFlow 适配器
│   │   └── main.py             # 应用入口
│   ├── alembic/                # 数据库迁移
│   ├── requirements.txt
│   └── Dockerfile
├── docker-compose.yml
└── .env.example
```

### 1.2 后端分层约定

```
请求 → api/（路由层）→ services/（业务逻辑）→ models/（ORM）→ DB
                         ↓
                    adapters/（AI 能力调用）
```

- **api 层**：只做参数校验、权限检查、调用 service、返回响应
- **services 层**：核心业务逻辑，可调用其他 service 与 adapter
- **models 层**：ORM 模型定义，不写业务逻辑
- **schemas 层**：Pydantic 模型，负责请求校验与响应序列化（字段级权限过滤在此层）

## 三、Git 工作流

### 3.1 分支策略（简化 Git Flow）

| 分支 | 用途 | 命名 |
| --- | --- | --- |
| `main` | 生产环境稳定版本 | - |
| `develop` | 开发集成分支 | - |
| `feature/*` | 功能开发 | `feature/ai-recommend` |
| `fix/*` | 缺陷修复 | `fix/login-redirect` |
| `hotfix/*` | 生产紧急修复 | `hotfix/share-token-bug` |
| `release/*` | 发布准备 | `release/v1.0.0` |

### 3.2 Commit 规范（Conventional Commits）

```
<type>(<scope>): <subject>

<body>
```

| type | 说明 |
| --- | --- |
| feat | 新功能 |
| fix | 缺陷修复 |
| docs | 文档变更 |
| style | 代码格式（不影响逻辑） |
| refactor | 重构 |
| test | 测试相关 |
| chore | 构建/工具变更 |

**示例：**
```
feat(product): 支持Excel批量导入产品

- 新增 /api/v1/products/import 接口
- 支持标准模板下载
```

### 3.3 PR 规范

- PR 标题遵循 Commit 规范
- PR 描述包含：变更说明、测试方式、影响范围
- 至少 1 人 Code Review 通过方可合并
- CI 通过（Lint + 测试）方可合并

## 四、数据库迁移规范

### 4.1 Alembic 工作流

```bash
# 修改 models 后生成迁移脚本
alembic revision --autogenerate -m "add share_token table"

# 执行迁移
alembic upgrade head

# 回滚
alembic downgrade -1
```

### 4.2 迁移注意事项

- 迁移脚本必须可逆（提供 `downgrade`）
- 数据迁移与结构迁移分开提交
- 禁止在迁移脚本中直接物理删除数据
- 生产环境迁移前先在 staging 验证

## 五、AI Adapter 开发规范

### 5.1 新增 AI 引擎适配器步骤

1. 在 `backend/app/adapters/` 下新建实现文件（如 `dify.py`）
2. 继承 `AIServiceAdapter` 抽象基类
3. 实现 4 个核心方法：`chat`、`chat_stream`、`parse_tool_calls`、`manage_session`
4. 在配置中注册适配器（`.env` 中 `AI_ADAPTER=dify`）
5. 编写适配器回归测试（见 [09-测试计划](./09-测试计划.md)）

### 5.2 适配器实现要求

- **接口契约一致性**：返回结构必须与基类定义一致（`answer`/`sources`/`tool_calls`）
- **错误隔离**：下游引擎异常不应导致业务层崩溃，统一转换为 `50201` 错误码
- **超时控制**：所有下游调用设置超时（建议 30s，流式 300s）
- **日志记录**：记录请求/响应摘要到 `AIConversation` 表

## 六、安全开发规范

| 场景 | 规范 |
| --- | --- |
| SQL 查询 | 必须使用 ORM 参数化查询，禁止字符串拼接 SQL |
| 密码存储 | bcrypt 加密，禁止明文/MD5 |
| 敏感字段 | 响应序列化层统一过滤（字段级权限） |
| 文件上传 | 扩展名白名单校验 + 文件大小限制 |
| XSS 防护 | 前端输出转义，后端输入过滤 |
| CSRF | JWT 鉴权天然防 CSRF，无需额外 Token |
| 越权检查 | 每个接口必须校验"当前用户是否有权操作该资源" |

### 6.1 密码策略

| 规则 | 要求 |
| --- | --- |
| 最小长度 | 8 位 |
| 复杂度 | 至少包含大写字母、小写字母、数字、特殊字符中的 3 种 |
| 禁止项 | 不得包含用户名、连续 3 位相同字符 |
| 存储 | bcrypt 加密（cost factor ≥ 12），禁止明文/MD5/SHA1 |
| 初始密码 | 管理员创建用户时生成随机初始密码，首次登录强制修改 |
| 失败锁定 | 连续 5 次登录失败锁定账号 15 分钟（Redis 计数） |
| 密码修改 | 修改密码需验证旧密码，新密码不能与最近 3 次相同 |

### 6.2 JWT 安全策略

| 规则 | 要求 |
| --- | --- |
| Token 有效期 | access_token 2h，refresh_token 7d |
| 签名算法 | HS256（MVP），V2 多租户演进 RS256（非对称） |
| Payload | 含 user_id / role_code / perms / iat / exp / jti |
| refresh 轮换 | 每次 refresh 生成新 refresh_token，旧 token 立即失效（防重放） |
| 登出黑名单 | 登出时将 access_token 的 jti 加入 Redis 黑名单，TTL 同 Token 剩余有效期 |
| Token 撤销 | 管理员可强制下线用户（删除 Redis 会话 + 加入黑名单） |
| 传输 | 仅 HTTPS 传输，禁止 URL 参数传递 Token |

## 七、日志规范

### 7.1 日志级别

| 级别 | 使用场景 |
| --- | --- |
| DEBUG | 开发调试信息 |
| INFO | 正常业务流程（用户登录、方案生成等） |
| WARNING | 异常但可恢复（限流触发、降级） |
| ERROR | 业务异常（接口报错、下游不可用） |
| CRITICAL | 系统级故障 |

### 7.2 日志内容要求

- 请求日志：method、path、user_id、ip、耗时、status_code
- 错误日志：异常堆栈、请求参数摘要、user_id、trace_id
- AI 调用日志：adapter 类型、引擎响应耗时、token 消耗

### 7.3 审计动作清单
