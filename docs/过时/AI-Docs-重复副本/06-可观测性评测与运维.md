# 06 可观测性、评测与运维

> 实施状态：**AI 上线目标与发布门槛，当前尚未全部达到。** 当前已有基础 HTTP/AI 指标、健康检查和运维状态接口；本章新增的 Gateway、检索、Worker、成本与质量指标待分期实现。

## 1. 运营原则

AI 质量不能只看接口是否 200。系统必须同时观测：业务正确性、检索质量、模型质量、权限安全、延迟、可用性和成本。

## 2. SLO 与容量基线

首期容量假设：

- 产品最多 1 万；
- 可检索知识块最多 10 万；
- 内部注册用户数十至低百位；
- AI 查询峰值 5 RPS，正常并发 20；
- 单文档上限 100MB，建议产品资料治理后控制在 50MB 内。

初始 SLO：

| 指标 | 目标 |
| --- | --- |
| Knowledge Gateway 月可用性 | ≥ 99.5%，不含模型明确关闭时段 |
| 查询错误率 | < 1%（供应商错误单列） |
| 首个可见事件 P95 | ≤ 2.5s |
| 完整回答 P95 | ≤ 12s，硬超时 30s |
| 只读工具 P95 | ≤ 500ms |
| 混合检索 P95 | ≤ 1.5s |
| 索引新鲜度 | 普通文档 95% 在 5 分钟内可检索 |
| 索引成功率 | ≥ 99%，排除不受支持/损坏文件 |
| 权限泄露 | 0 |
| 动态字段由文档错误回答 | 0 |

AI SLO 不得降低现有产品列表、详情和写操作的 `RELEASE_GATE.md` 性能目标。若资源争用，优先保护核心 PIM。

## 4. Trace 与日志

每个查询生成 UUID `trace_id`，通过响应 Header、SSE meta、Gateway、工具、检索、模型和动作审计传播。索引任务独立 `job_id`，保留触发 trace。

结构化日志允许字段：时间、trace、action、provider、model、latency、token、结果数量、错误码。禁止字段：Prompt、回答原文、知识块正文、JWT、API Key、客户名称、成本值。

错误分类统一：

- `AUTH_DENIED`
- `POLICY_BLOCKED`
- `PLAN_INVALID`
- `TOOL_TIMEOUT/TOOL_FAILED`
- `RETRIEVAL_EMPTY/RETRIEVAL_FAILED`
- `MODEL_TIMEOUT/MODEL_RATE_LIMIT/MODEL_INVALID`
- `CITATION_INVALID`
- `ACTION_CONFLICT`
- `INDEX_PARSE_FAILED/INDEX_EMBED_FAILED`

## 5. 告警

P0/P1 告警：

| 条件 | 等级 | 处置 |
| --- | --- | --- |
| 检测到权限泄露或敏感字段出域 | P0 | 关闭相关工具/模型路由，保留证据并启动安全事件流程 |
| 核心 PIM 被 AI 负载拖慢越过门禁 | P0 | 限制 AI 并发或关闭 AI，不牺牲核心业务 |
| Gateway 5xx > 5% 持续 5 分钟 | P1 | 检查供应商、DB、Redis，启用降级 |
| 模型超时/限流 > 10% 持续 10 分钟 | P1 | 熔断并提示不可用，禁止无限重试 |
| Dead jobs > 0 | P1 | 人工检查错误分类并重放或标记不可处理 |
| 最老索引任务 > 15 分钟 | P1 | 检查 Worker 和供应商容量 |
| 日成本达到日预算 80% | P1 | 通知并收紧额度；100% 按策略停用非关键能力 |

## 6. 成本治理

- 设置系统、角色和用户三级频率限制；
- 限制最大输入、历史、候选块和输出 Token；
- Query Planner 使用小模型或规则，不默认使用最昂贵模型；
- Embedding 批处理，按 content hash 去重；
- 相同模型和 pipeline 下不重复索引未变化内容；
- 缓存仅用于非敏感、权限一致的检索中间结果；
- 每日按能力统计费用：规划、回答、Embedding、重排；
- 预算超限时先关闭非关键重排和后台批量重建，不自动切换到未经评测的模型。

## 7. 离线评测集

上线前建立版本化中文评测集，建议首期不少于 200 条：

| 类别 | 最少数量 | 重点 |
| --- | --- | --- |
| 精确产品/型号 | 30 | 连字符、别名、相似编号 |
| 场景选型 | 40 | 多条件、未知价格库存 |
| 多产品比较 | 30 | 属性缺失、证据平衡 |
| 说明书问答 | 40 | 页码、表格、警告、拒答 |
| 数据治理 | 25 | 待核价、缺图、缺资料、草稿 |
| 采购辅助 | 20 | 字段权限、数据不足 |
| 安全对抗 | 30 | Prompt 注入、越权、密钥、任意 SQL |
| 无答案/歧义 | 20 | 澄清、拒答、来源冲突 |

每条样本包括：问题、用户角色/权限、scope、期望实体、允许工具、禁止字段、期望来源、参考答案要点和是否应拒答。不得把生产原始对话未经审批直接加入评测集。

## 8. 质量指标与门槛

### 8.1 检索

- 产品实体精确识别率 ≥ 98%；
- 说明书 Recall@10 ≥ 90%；
- 引用定位准确率 ≥ 95%；
- 无答案识别 F1 ≥ 85%；
- 多产品比较的产品证据覆盖率 ≥ 95%。

### 8.2 端到端

- 结构化事实准确率 100%；
- 动态字段通道合规率 100%；
- 权限与敏感字段测试 100% 通过；
- 有证据回答的引用支持率 ≥ 95%；
- 推荐 Top5 人工相关率 ≥ 80%（试点数据完善后评测）；
- AI 写动作未经确认执行次数为 0；
- 安全对抗集阻断率 100%，正常业务误拦截率 < 2%。

若达不到硬门槛，不以调整阈值掩盖问题；需要标记场景不支持或回到数据治理。

## 9. 在线反馈与质量闭环

反馈选项：有用、无用、产品不相关、事实错误、来源不支持、资料过期、权限问题、回答不完整。流程：

```text
用户反馈
→ 绑定 trace 和来源
→ 产品/知识/模型/权限问题分类
→ 指派数据治理或研发
→ 修复数据、检索、Prompt 或代码
→ 加入脱敏回归集
→ 重新评测后发布
```

不使用简单点赞直接调整在线排序，避免小样本污染。

## 10. 故障与降级

| 故障 | 用户表现 | 系统行为 |
| --- | --- | --- |
| Chat 模型不可用 | 提示 AI 生成暂不可用 | 可返回确定性产品搜索结果，不编造解释 |
| Embedding 不可用 | 语义搜索降级 | 保留精确和关键词通道 |
| Redis 不可用 | AI 查询 503 或受控本机限流 | 不允许无保护放开；核心 PIM 正常 |
| Worker 不可用 | 新文档显示排队/延迟 | 旧索引继续服务，上传业务不回滚 |
| OCR 不可用 | 扫描件标记需 OCR | 不伪装解析成功 |
| 数据库压力高 | AI 限流/熔断 | 优先保护产品、方案、报价接口 |
| 引用校验失败 | 不发送高置信答案 | 返回资料不足或无引用草稿标识 |

## 11. 备份与恢复

- `knowledge_document/chunk/job/feedback` 随 PostgreSQL 现有备份恢复；
- 原始附件随 MinIO 备份恢复；
- 向量可重建但仍纳入数据库备份，以缩短 RTO；
- Redis Streams 不作为最终事实，丢失后由 PostgreSQL pending/dispatched jobs 重投；
- 恢复演练增加：知识表行数、随机来源可打开、向量维度、Worker 重投和 Gateway 查询；
- 沿用项目 RPO ≤ 24h、RTO ≤ 4h，另设索引恢复目标：业务恢复后 24 小时内可全量重建 10 万块。

## 12. 容量测试

建立四档数据：当前 13 产品、1x（1 万产品/10 万块）、2x、失效与重建压力场景。测试：

- 精确、FTS、向量和混合查询延迟与 Recall；
- 20 并发 AI 查询时核心 PIM P99；
- Worker 批量重建与在线查询共存；
- 单大文档、OCR 失败、供应商限流；
- HNSW 带 product/category 过滤后的实际召回数量；
- PostgreSQL 连接池按 Web 与 Worker 分配，确保 Worker 不耗尽连接。
