# 云端更新包

云端更新包用于已有生产环境升级，不包含 PostgreSQL、Redis、MinIO 数据、备份、`.env`、日志、Docker volume 或真实凭据。云端已有数据必须先完成独立备份。

## 包内容

- 当前 Git 源码快照
- `README.md`、`README_EN.md` 和当前运行文档
- backend、frontend、portal 源码与锁定依赖清单
- Docker Compose、nginx、OCR 和构建脚本
- Alembic 迁移及种子脚本
- `UPDATE_README.md`
- `1.9.1-V-Log.md`

## 升级顺序

```bash
bash scripts/where-am-i.sh
export PATH="$HOME/.nvm/versions/node/v24.18.0/bin:$PATH"
bash scripts/build_frontends.sh
export APP_VERSION=1.9.1
export BUILD_ID=<build_frontends.sh 输出值>
export GIT_COMMIT=<当前提交>
export BUILD_TIME=<构建时间>
export APP_ENV=production
docker compose up -d --no-deps backend nginx
docker exec richangpim-backend-1 alembic current
HEALTH_URL=http://127.0.0.1:888/api/v1/health ./scripts/healthcheck.sh
```

升级前先用 `docker exec` 对生产 PostgreSQL 做 `pg_dump -Fc`，并确认 MinIO 备份状态为 `ok`。backend 启动入口会自动执行迁移、管理员初始化和种子数据。

## 明确不包含

- PostgreSQL dump 或数据库卷
- MinIO 对象或 MinIO volume
- Redis volume
- `.env`、`AI.env`、`embedding.env`
- `backups/`、日志、测试结果和构建缓存

发生回滚时保留旧镜像，使用 `docker compose up -d --no-deps <service>` 回切，并按迁移兼容性评估数据库是否需要恢复。
