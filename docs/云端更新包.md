# 云端更新包

云端更新包用于已有生产环境升级，不包含 PostgreSQL、Redis、MinIO 数据、备份、`.env`、日志、Docker volume 或真实凭据。云端已有数据必须先完成独立备份。

## 包内容

- 当前 Git 源码快照
- `README.md`、`README_EN.md` 和当前运行文档
- backend、frontend、portal 源码与锁定依赖清单
- Docker Compose、nginx、OCR 和构建脚本
- Alembic 迁移及种子脚本
- `UPDATE_README.md`
- `<version>-V-Log.md`（发版时在仓库根目录创建，包内文件名与版本号一致）

## 新增索引与数据字段的打包要求

开发端新建了任何**数据库索引**（`pg_trgm`、HNSW、普通 B-tree 等）、**新表/新列**、**受治理属性定义/选项/别名**，或**种子与 mapping 数据**时，必须同时满足以下三条，缺一条即视为打包不完整：

1. **必须能随包分发**：以迁移脚本、种子脚本、mapping JSON 或随包文档的形式进入更新包，不允许只存在于开发机本地库。本地库里手工 `insert`/`create index` 出来的东西，生产永远拿不到。
2. **必须在包中注明**：`UPDATE_README.md` 要有「本版索引与数据字段变更」一节，逐条写清：改了什么、由包内哪个文件承载、升级后是**自动生效**还是**需要手动步骤**、以及验收方式。
3. **必须区分自动与手动**：
   - 随容器启动自动执行：Alembic 迁移，以及 entrypoint 里的 `init_admin`、`seed_data`、`seed_default_skills --apply`、`seed_attribute_dictionary --apply`（属性词典种子）；
   - **必须手动执行且要写进升级步骤与验收清单**：产品属性值回填 `python -m app.scripts.backfill_product_attributes --apply`、一次性维护脚本 `fix_category_option_codes --apply` 等。这类步骤 entrypoint 刻意不自动跑（注释见 `backend/docker/backend-entrypoint.sh`），包里不写就没人知道要跑。

打包前自检：mapping/种子数据文件非空、必填字段齐全，并被 `checksums/sha256sums.txt` 与 `MANIFEST.txt` 覆盖；新增索引有对应迁移，且迁移链与生产 `alembic_version` 线性衔接。

> 教训实例（v1.9.4 → v1.9.5，118.195.250.183）：属性检索的代码、词典种子、别名与 mapping 都随包部署到位，但 `product_attribute_value` 生产为 0 行——回填是手动步骤，而 v1.9.4/v1.9.5 的 `UPDATE_README` 都没写它，于是「弧形会议桌」在生产一直返回空。补齐 `--apply` 后立即恢复。新增数据字段时，先问一句「这一步在生产谁来跑、跑什么命令」，写进包里。

## 升级顺序

```bash
bash scripts/where-am-i.sh
export PATH="$HOME/.nvm/versions/node/v24.18.0/bin:$PATH"
bash scripts/build_frontends.sh
export APP_VERSION=<版本号，如 1.9.3>
export BUILD_ID=<build_frontends.sh 输出值>
export GIT_COMMIT=<当前提交>
export BUILD_TIME=<构建时间>
export APP_ENV=production
docker compose up -d --no-deps backend nginx
docker exec richangpim-backend-1 alembic current
HEALTH_URL=http://127.0.0.1:888/api/v1/health ./scripts/healthcheck.sh
```

升级前先用 `docker exec` 对生产 PostgreSQL 做 `pg_dump -Fc`，并确认 MinIO 备份状态为 `ok`。backend 启动入口会自动执行迁移、管理员初始化与种子数据（`init_admin` / `seed_data` / `seed_default_skills` / `seed_attribute_dictionary`）；**产品属性值回填等数据步骤不会自动执行，必须按本包 `UPDATE_README` 手动执行**（见上一节）。

## 明确不包含

- PostgreSQL dump 或数据库卷
- MinIO 对象或 MinIO volume
- Redis volume
- `.env`、`AI.env`、`embedding.env`
- `backups/`、日志、测试结果和构建缓存

发生回滚时保留旧镜像，使用 `docker compose up -d --no-deps <service>` 回切，并按迁移兼容性评估数据库是否需要恢复。
