# RiChangPIM v1.9.8 Version Log

Release date: 2026-10-30

## Release Scope

This release rebuilds the product-list category filter as a three-level navigation,
adds a delivery-period field to products, and makes product and manual changes
automatically rebuild knowledge cards (including optional vision tagging of product
images). The portal comparison table gains product thumbnails plus Markdown and PDF
export.

## Main Changes

- **Three-level product filter**: new `GET /api/v1/products/filter-options` returns
  level-2 and level-3 options with counts for six dimensions (series, brand, supplier,
  status, stock, category), aggregated live from product data. The series dimension
  uses series tags for level 3 while the category dimension uses the first segment of
  the specification string, so identically named level-2 entries never share level-3
  data. Product list and export accept new `tag_type` and `spec_length_mm` filters, and
  category filtering now includes all descendant categories.
- **Delivery period**: `product.delivery_period` is wired through API schemas, import
  header aliases, the import template, export columns, product list/detail screens and
  the edit form, keeping the export-edit-reimport loop closed.
- **Automatic knowledge reindexing**: product create/update/delete/clone, image changes,
  bulk imports and manual create/parse/OCR/delete now enqueue index jobs through
  `KnowledgeJobDispatcher`. Product cards additionally carry category path, delivery
  period and vision tags.
- **Optional product-image vision tagging**: new tagger module and
  `ai_provider_config.vision_model` setting; when no vision model is configured the
  whole step is skipped and indexing is unaffected.
- **Detail page and portal**: the product detail page gains a hero image with a
  lightbox; the portal comparison table gains thumbnails, Markdown export and a PDF
  export endpoint backed by Gotenberg.

## Database and Index Changes

- Migration `0034_user_token_version` adds `user.token_version` (carried over from the
  previous release line).
- Migration `0035_knowledge_chunk_partial_unique` replaces the
  `knowledge_chunk` unique index with a partial index that only covers non-deleted
  rows, so rebuilt documents no longer collide with soft-deleted history.
- Migration `0036_product_delivery_period_vision_tags` adds `product.delivery_period`,
  `product_image.vision_tags` and `ai_provider_config.vision_model`.

All three migrations run automatically when the backend container starts. No data
backfill is required. Refreshing existing product cards (to pick up the new fields and
vision tags) is an optional manual step:
`docker exec richangpim-backend-1 python -m app.scripts.knowledge_indexer --once`.

## Compatibility and Upgrade Notes

- The migration head advances from `0033_sales_media_permissions` to
  `0036_product_delivery_period_vision_tags`.
- Back up PostgreSQL and MinIO before deployment. Keep the previous backend and nginx
  images available until post-deployment acceptance is complete.
- Vision tagging requires a multimodal model. Leave `AI_VISION_MODEL` (or the AI
  configuration center entry) empty to disable it; a text-only model will fail index
  jobs.
- Known issue (not fixed in this release): the specification numeric expression in
  `backend/app/knowledge/tools/product.py` uses `func.instr`, which PostgreSQL does not
  provide, so AI product search sorted or filtered by length/width/height fails. The
  admin product filter avoids that expression.

## Package Boundary

This update package contains source code, configuration templates, migrations, build
scripts and release notes only. It excludes PostgreSQL dumps, MinIO objects, Redis
volumes, `.env` files, backups, logs and build caches. The full migration bundle is a
separate artifact described in `MIGRATION_BUNDLE.md`.
