# RiChangPIM v1.9.4 Version Log

Release date: 2026-10-23

## Release Scope

This release merges three capability tracks — governance-backed product-attribute retrieval, the content Skills / topic module, and proposal space labels with customer sharing — and realigns the local Alembic chain onto the production `0024_attachment_biz_domain_compat` baseline so a server upgrade no longer fails on an unknown revision. As part of the same release, three UI issues reported during acceptance are fixed: the content workshop's DNA-source selector is renamed to 「创作 Skills」so a writing Skill is no longer confused with the DNA it came from; the proposal creation dialog is re-laid out so item fields are not squeezed into a horizontal scroller; and the shared proposal page shows only a summary table, with full product details revealed in a dialog after a click.

## Main Changes

- Product attributes: a governed attribute dictionary (category, shape, style, material, colour, series, size, seat count) with Chinese aliases, no-space forms, numeric and negated conditions; `product.search` applies hard facets (AND across attributes, OR across aliases), and `shape` only matches the shape facet.
- Content Skills: `skills/manage` admin-only centre, `topics/runs` generation, operational Skill routing with a deterministic fallback; `CONTENT_AI_*` configuration with a two-model whitelist; JSON-schema validation, compliance guard and product-fact back-checking are kept.
- Proposals and sharing: free-text floor/space labels with snapshot storage, product snapshots, PDF columns for location/material/colour, and grouped display on the customer share page.
- UI fixes: content workshop field 「DNA 来源」 → 「创作 Skills」 (Skill name shown, DNA as secondary text); proposal creation dialog 640px → 920px with top-aligned two-column rows and a `compact` item editor grid; share page summary tables plus a per-product detail dialog (specification, material, colours, material notes, prices, scene-image grid) with the carousel opening at the clicked image.
- Migrations: `0018_qwen_embedding_hnsw`, `0019_crm_base_tables`, `0023_crm_sales_links_compat`, `0024_attachment_biz_domain_compat` taken from the production image; `0025_crm_schema_compat`, `0026_catalog_attributes`, `0027_content_skills`, `0028_project_spaces`, `0029_project_remark`, `0030_content_dna_fields` (head). The old local `0018_crm_core` / `0019_crm_detail` were moved to `backend/alembic/versions/回收站/`, not deleted.
- Version unification at 1.9.4: `frontend/package.json`, `portal/package.json`, both lockfiles, `backend/app/core/config.py` `VERSION`, `docker-compose.yml` `APP_VERSION` fallback, `README.md`, `AI-Docs/README.md`, `CHANGELOG.md`.

## Compatibility

- Application version: `1.9.4` (anchor `frontend/package.json`; compose fallback also says `1.9.4` so a forgotten build arg no longer reports `dev`).
- Database migration head: `0030_content_dna_fields`. A production database on `0024` advances through `0025 → … → 0030`; all steps are idempotent DDL and do not recreate existing tables or columns.
- Existing PostgreSQL, Redis and MinIO volumes must be preserved; the update package contains no business data, objects or secrets.
- New `CONTENT_AI_*` environment variables are optional; compare `.env.example` before upgrading. Without a content AI key the content endpoints answer 503 by design.

## Upgrade Notes

1. Back up PostgreSQL (`pg_dump -Fc`) and confirm the MinIO backup state is `ok`.
2. `bash scripts/build_frontends.sh` (Linux Node must be on `PATH`, e.g. `export PATH="/root/.nvm/versions/node/v24.18.0/bin:$PATH"`), then record `BUILD_ID` / `GIT_COMMIT` / `BUILD_TIME`.
3. Export `APP_VERSION=1.9.4`, `APP_ENV=production` and the recorded metadata, then `docker compose build backend nginx` and `docker compose up -d --no-deps backend nginx`.
4. Verify `alembic current` → `0030_content_dna_fields (head)`, `/api/v1/health`, `/api/v1/version`, and the 「系统管理 → 版本」 page (all four rows real, 「一致」).
5. Spot-check the changed screens: content workshop 「创作 Skills」 selector, proposal creation dialog layout, shared proposal detail dialog.

## Known Risks

- When the content AI model is slow, `POST /api/v1/content/batches` times out at `CONTENT_AI_TIMEOUT` (180 s); the workshop then shows the generic 「网络连接失败」 banner because the frontend interceptor maps non-2xx responses to that text. This is an AI-service latency issue, not a UI defect.
- The share API does not expose a per-item remark, so the product detail dialog cannot show it; adding it requires a backend field in `_build_content`.
