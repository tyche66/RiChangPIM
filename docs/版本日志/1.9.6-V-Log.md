# RiChangPIM v1.9.6 Version Log

Release date: 2026-10-28

## Release Scope

This release ships the first batch of the governed product-attribute index for 20 product
series, fixes the empty-result failure of natural-language product queries ("现代风格"
returned nothing), adds a two-stage semantic fallback behind the exact structured layer,
adds a browser-local query history to the AI portal, and fixes the AI Config Centre, where
a saved provider change silently reverted to the environment value after about 15 seconds.

## Main Changes

- **Series attribute index (20 series)**: `seed_attribute_dictionary` gains `SERIES_OPTIONS`
  (20 series options + 65 aliases, `option_code` = series `tag_name`, so "灵多系列" resolves).
  `backfill_product_attributes` gains series (+ optional category) entries that expand through
  `product_tag` to every in-sale product of the series. New
  `backend/app/scripts/data/series_attribute_mapping.json` carries 217 series-level rules
  (series / style / shape / material / color). Local `--check`: created=17879, skipped=0,
  unresolved=0; a second `--apply` run yields created=0 (idempotent).
- **Business confirmation**: all 197 AI candidates (`verified=false`) are now `verified=true`
  after a line-by-line confirmation on 2026-10-27 — 20 series, style/shape/material/colour
  values confirmed as-is. `source` is unchanged (`ai_inferred` keeps AI provenance) so rollback
  stays a precise soft delete by source + write date. Confirmation scope/owner/date are recorded
  in `_confirmed_by` / `_confirmed_at` / `_confirmed_scope`.
- **Natural-language retrieval — three root causes fixed**: the rule layer only matched
  dictionary aliases; the model planner received an attribute context containing option codes
  only (no Chinese labels or aliases), so it could not map "现代风格" to `modern`; and pure
  English words were captured by the model-number regex, so "modern" became
  `product_no IN ('modern')` and filtered every style hit to zero. Aliases now cover the
  "…风格/…风" suffix and English names per option, the dictionary context carries labels and
  aliases, and model-number extraction requires a digit or `-._/` (all 4024 in-sale model
  numbers contain digits) plus dictionary-alias exclusion.
- **New `app/knowledge/semantic.py` — the semantic pass after keyword retrieval**: when the
  exact layer returns nothing, `resolve_facets` asks the model to normalise the whole sentence
  into governed attribute values (dictionary-validated, hallucinated attributes/values are
  dropped) and re-runs the exact SQL; if that still yields nothing, `screen_products` screens
  the relaxed/text-recall candidates and returns the best fits. If neither applies, the result
  stays empty — "巴洛克式会议桌" must remain empty. Responses carry `semantic_interpretation`.
- **Structural suffix stopwords**: "风格/样式/款式/系列" no longer survive as AND keywords
  (the leftover "风格" from "现代简约风格" previously cleared the result set).
- **Portal query history**: browser-localStorage history (`richangpim.portal.queryHistory.v1`,
  30 entries, query text + timestamp only, silent degradation when storage is unavailable),
  click-to-rerun, and a timestamp on the "本次查询" echo. No new server-side storage.
- **AI Config Centre**: a saved provider change reverted to the environment value after about
  15 seconds because the config snapshot expired and `get_config` fell back to env. Expired
  snapshots are now still served, and a periodic refresher (interval below the TTL) keeps the
  snapshot equal to the DB override layer. DB flapping still keeps the last snapshot.

## Compatibility and Upgrade Notes

- Migration head is unchanged: `0031_ai_provider_config`. No database migration ships in this
  release; the attribute dictionary and options are data, created by the seed script.
- The dictionary seed runs **automatically** at backend container start
  (`seed_attribute_dictionary --apply`, idempotent) — the series options and the new aliases
  appear without any manual step.
- **The attribute backfill is a manual step** and is deliberately not run by the entrypoint:
  `docker exec richangpim-backend-1 python -m app.scripts.backfill_product_attributes --check
  --mapping app/scripts/data/series_attribute_mapping.json` then `--apply`, then a second
  `--apply` to prove idempotency (created=0). Acceptance: series options = 20,
  `style=new_chinese` = 175, no `verified=false` rows in the batch, and the knowledge gateway
  answers "现代风格" / "灵多系列职员桌" with products while "巴洛克式会议桌" stays empty.
- Rollback is a soft delete of `product_attribute_value` by `source` + write date (never a
  hard delete, never a table truncate); the series options are soft-deleted, not dropped.
- AI Config Centre behaviour change: a DB override now keeps taking effect until it is changed
  again. An empty cache (before first warm-up) still falls back to environment variables.
- Portal query history lives only in the browser; clearing browser data clears the history, and
  nothing is written to or read from the server.
