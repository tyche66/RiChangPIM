# RiChangPIM v1.9.7 Version Log

Release date: 2026-10-29

## Release Scope

This release adds proposal floor-plan attachments to the admin and public sharing
experience, and replaces the product re-upload flow with a preflight step followed by
an explicit overwrite, append, or skip operation.

## Main Changes

- **Proposal floor plans**: adds the `proposal_floor_plan` table in migration
  `0032_proposal_floor_plans`, proposal floor-plan APIs, attachment reference checks,
  admin management controls, and a zoomable floor-plan viewer on the public share page.
  Image objects remain in the media library; removing a proposal binding does not delete
  the underlying media.
- **Sales media access**: migration `0033_sales_media_permissions` grants the `sales`
  role `media:view` and `media:upload`, without granting media deletion or replacement.
- **Product package re-upload**: adds a zero-write preflight endpoint and a one-time
  commit token for `overwrite`, `append`, or `skip`. Overwrites preserve a JSON snapshot
  that can be inspected and restored with the packaged restore script.
- **Import merge rules**: omitted spreadsheet fields preserve existing values; append
  fills only empty fields; image replacement and append are handled separately; labels
  can be created from typed spreadsheet values or the preflight default.

## Compatibility and Upgrade Notes

- The migration head advances from `0031_ai_provider_config` to
  `0033_sales_media_permissions`. Both migrations run automatically when the backend
  container starts. No manual data backfill is required.
- Back up PostgreSQL and MinIO before deployment. Keep the previous backend and nginx
  images available until post-deployment acceptance is complete.
- The import preflight files use `PRODUCT_IMPORT_STAGING_DIR` (default
  `/tmp/pim_import_staging`) and expire after `PRODUCT_IMPORT_STAGING_TTL_SECONDS`
  (default 7200 seconds). The preflight token is single-use for commit.
- Database downgrade drops the floor-plan relation and its bindings; assess whether
  those records must be retained before rollback. Media objects themselves are not
  deleted by the migration or by removing a floor-plan binding.
