## 一、本轮已闭环的阻断项

### 1. 类目属性 UUID 编码（原阻断项 1）

**结论：已修复并验证。**

* 本地库原先 313 个 category 选项中有 158 个 `option.code` 是 32 位 UUID。
* 诊断结论：这 158 个全部是**重复行**——每个都能在同属性下找到一个 `code = label`
  （类目名）的正统选项，且每条只有 1 个别名、与正统选项的别名完全相同、
  没有任何 `product_attribute_value` 引用。因此正确动作是「合并后软删」，
  而不是「改名」（改名会直接撞 `uq_cao_attribute_code` 唯一约束）。
* 重写了 `backend/app/scripts/fix_category_option_codes.py`：
  * 无冲突时改名 + 保留既有别名、补 label 别名（不再覆盖别名）；
  * 有冲突时把孤儿独有的别名/产品取值迁到正统选项（冲突时保留更可信的一条），
    再软删孤儿选项本身；**不硬删任何数据**；
  * `--check` / `--apply` 双模式，输出 `renamed/merged/skipped/aliases_*` 计数。
* 执行结果（本地库 `ai_pim`）：

| 阶段 | category 选项 | UUID code | category 别名 | 无别名的选项 | 产品属性值 |
| --- | --- | --- | --- | --- | --- |
| 修复前 | 313 | 158 | 313 | 0 | 3 |
| 修复后 | 155 | **0** | 155 | 0 | 3 |

* 复核：`python -m app.scripts.fix_category_option_codes --check` → `renamed=0 merged=0`；
  全部 155 个选项的 label 都能在 Category 树里按名匹配，无覆盖缺口；
  其它属性（shape/material/color/style）本来就没有 UUID code。
* 回归（本地库真实查询）：`弧形会议桌` / `弧型会议桌` / `圆弧形会议桌` → 精确命中
  `P-104300001 / P-104300002 / P-104300003`；`弧形洽谈桌`、`新中式弧形会议桌` → 0 命中；
  `弧形 会议桌，不要黑色`（带空格+标点+否定）→ 3 个 SKU 命中。

### 2. 属性解析坐标错位（审查在阻断项 5 中点名）

**结论：已修复并新增回归测试。**

`normalize_text()` 会删空白/标点并 casefold，`extract_alias_hits()` 原先返回的是
**归一化串**上的命中位置，而 `_residual_text()` 用这些位置切**原文**。带空格、标点、
中英混排的查询会把残余词切错（例：`"弧形 会议桌，不要黑色"` 会把 `，不` 抹掉，
残留出 `要黑色`）。

* 新增 `normalize_text_with_map()`，返回「归一化下标 → 原文下标」映射；
* `extract_alias_hits()` 现在把命中位置换算回原文坐标（`AliasHit.start/end`）；
* 顺带修掉两个真实缺陷：
  1. 否定词本身会残留在软词里（`不要黑色` 会残留出 `不要`）——现在被否定的命中
     连同否定词一起从残余文本里抹掉；
  2. 产品型号会变成软词（`EN74-2.320162` 会残留出 `EN74-2`）——现在按
     `product_nos` 一并抹掉（走 planner 路径时已生效）。
* 新增测试 `backend/tests/unit/test_attribute_parser_offsets.py`（44 条）：
  坐标映射、否定变体（空格/标点/「非」）、语序变化、编号混排、属性组合、
  未知词不静默丢弃、精确/部分分层（`match_tier`）。

### 3. 独立选题真实生成（原阻断项 2）

**结论：已补齐完整链路，并有 HTTP 级冒烟验证。**

新增 `backend/app/services/topic_service.py`：

* 用所选 Skill 的 `prompt_template`（缺省退回内置模板）渲染提示词，占位符缺失
  不炸（未知占位符原样保留，模板非法时退回默认）；
* 调用 AI 适配器拿 JSON（容忍 ```json 代码围栏）；
* 按 Skill 的 `output_schema`（缺省退回内置 schema）做子集校验；
* 逐条合规检查（承诺性措辞 + 广告法极限词），不通过的条目丢弃并计数；
* 落库 `ContentTopicItem`（带 `source_skill_code` 便于回溯「选题来自哪个 Skill」），
  run 从 `running` 推到 `done` / `failed`，失败写 `error_msg` + `latency_ms`。

API 变化：

* `POST /content/topics/runs`：AI 不可用 → 503（`50302`）、非法 JSON → 422、
  schema 不符 → 422、全部条目不合规 → 422；成功返回**真实生成的条目列表**；
* `POST /content/topics/items/{id}/adopt`：采纳即预建内容批次（标题/角度/人群/产品
  都带过去），返回 `content_batch_id`；
* 新增 `GET /content/topics/items/{id}`：返回 `topic_context`（标题+角度+人群+理由）、
  `skill_code`、`run_topic`，供内容工坊预填；
* `POST /content/batches` 新增可选 `topic_item_id`：生成成功后把选题条目推到
  `used` 并回写 `content_batch_id`（闭环）。

前端：

* `ContentTopics.vue`：显示 run 状态（生成中/已完成/失败）+ 失败原因，采纳后
  「带去内容工坊」带上 `topic_id` 与 `batch_id`；
* `ContentWorkshop.vue`：读取 `?topic_id=` 拉取选题详情，预填平台/标题/主题
  （含角度与人群）/关联产品，生成时带 `topic_item_id`；
* `api/content.ts`：新增 `getTopicItem` 与 `ContentTopicItemDetail` 类型。

新增测试 `backend/tests/unit/test_topic_generation.py`（24 条）：提示词渲染、
JSON 抽取、schema 校验、合规、AI 不可用/非法 JSON/schema 违规/全部不合规/空结果
六类失败路径、采纳预建批次。

**HTTP 级冒烟（本地库 + 假适配器）实测通过**：run→done(2 条) → 采纳(建批次)
→ 详情 → 用选题生成内容 → 条目 `used` 且回写批次 → 无 AI 503 → 坏 JSON 422
→ 失败 run 落库带原因。

### 4. 方案 → 报价 → 客户展示链路（原阻断项 3）

**结论：已补齐全链路，并有端到端测试。**

* **修复两个此前会让接口 500 的真实缺陷**：
  1. `ProposalItem` 模型**缺** `project_space_id / floor_label / space_label /
     material_desc / product_snapshot` 五列（0025 迁移加了列、ORM 没加），
     创建方案明细时直接 AttributeError；
  2. `build_product_snapshot()` 访问 `product.category` 触发延迟加载，
     异步 session 下抛 `MissingGreenlet`（创建方案 500）；已改 eager load。
     同样的问题也出现在 `proposals.py` 与 `share_token.py` 的产品批量查询里，
     已一并修复。
* **补齐 `projects.remark`**：`ProjectCreate` / `_project_to_dict` 都带 `remark`，
  但模型与迁移里都没有这一列，`POST /api/v1/projects` 必然 500。新增迁移
  `0026_project_remark`（纯增量、可空）。
* **报价明细**：`QuotationItemBase` 新增四个空间字段；创建/更新报价时写入，
  并在服务端生成产品快照（**优先沿用方案明细的快照**，保证口径一致）；
  `_enrich_quotation_item` 输出空间字段 + 快照派生字段。
* **PDF**：把 HTML 构建抽成 `_build_quotation_html()`，表格新增
  楼层 / 空间 / 材质说明 / 颜色 四列（明细优先、快照兜底、缺失显示 `-`）。
* **前端**：`Quotations.vue` 的「从方案预填」现在完整复制楼层/空间/材质说明/快照，
  提交时随明细带上，创建/编辑行与详情表格都展示位置与材质；
  `ProposalDetail.vue` 商品信息列展示楼层/空间与材质说明。

新增端到端测试 `backend/tests/test_track_c_proposal_quotation_e2e.py`（2 条，
需 Postgres 测试库，连不上则 skip 而非假装通过）：
