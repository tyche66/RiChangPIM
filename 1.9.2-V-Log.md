# RiChangPIM v1.9.2 Version Log

Release date: 2026-09-29

## Release Scope

This patch release fixes the three defect classes in the AI portal query result area (deck degradation to a plain grid, missing images on recommendation cards, raw Markdown output), reworks dark mode for both admin and portal from per-page `:global(.dark-mode)` overrides to a semantic-token implementation, and adds a non-Docker local one-command stack script. Two follow-up commits (dark-mode token rework and Beijing-time build metadata) sit on `main` after the annotated tag `v1.9.2`; per `版本控制规范和Git.md` §8 the tag was not moved and they belong to this release line.

## Main Changes

- `HeroDeck.vue` rewritten: five fixed card slots with a circular-window rotation, wheel/keyboard/narrow-screen stepping, gesture merging; the old `products.length <= 9` fan-vs-grid branch is removed and the deck is always the fan component.
- `ProductCard.vue`: image field compatibility with failure fallback, `data-image-state="ok|error|missing"` state split, fixed `aspect-ratio` so card height is stable before and after image load.
- `AnswerBody.vue` renders Markdown via the new dependency-free `utils/markdown.ts` (escape-on-output model) and `utils/image.ts` (field fallback + protocol allowlist); `citations.ts` gains `answerSource()` / `citationInfoOf()`.
- Dark mode rework (admin + portal): semantic tokens in `design-system.css` / `portal/src/styles/main.css`, full Element Plus dark variable set, `useTheme.ts` / `portal theme.ts` applying the theme class before Vue mounts, 29 views migrated to tokens, all `:global(.dark-mode)` blocks removed.
- `scripts/start_local_stack.sh`: non-Docker local dev stack start/stop/restart/status (nginx :888 + backend :8000 + local PG + redis + minio).
- `scripts/reembed_missing.py` added; `windows_demo_ports.ps1` forward target changed from 5173 to 888.
- Build metadata timestamps now use Beijing time (`TZ=Asia/Shanghai`), including CI.
- No backend route, model, or schema changed; the only `backend/` diff since v1.9.1 is the `VERSION` fallback in `app/core/config.py`.

## Compatibility

- Database migration head: `0017_operation_log_username`

- The cloud update package contains no production database, MinIO objects, Redis data, environment secrets, or backups.

## Upgrade Notes

1. Back up PostgreSQL and MinIO before replacing application containers.
2. Build both frontends with `bash scripts/build_frontends.sh`.
3. Export matching `APP_VERSION`, `BUILD_ID`, `GIT_COMMIT`, `BUILD_TIME`, and `APP_ENV=production` values before building backend and nginx images; the compose default `APP_VERSION=dev` makes the admin half of the version page render `—`.
4. Recreate only backend and nginx with `docker compose up -d --no-deps backend nginx`.
5. Verify `/api/v1/health`, `/api/v1/version`, `/admin/`, the version page consistency check, the portal query deck (rotation, card images, Markdown answers, citations), and dark mode in both themes.
6. Theme choice moved to `localStorage['theme']` with `light / dark / system`; users see the light theme once after upgrade if their browser previously relied on the old per-page override.

## Known Risks

- Release gate not fully run: backend full `pytest` and admin `playwright test` were not run this round; completed substitutes were `vue-tsc --noEmit`, frontend/portal builds, portal e2e (desktop + mobile projects), and headless dark-mode checks with a WCAG contrast audit.
- Portal narrow screens (<=1024px) intentionally keep the scroll-snap card strip, not the fan.
- Backend `is_cover` semantics unchanged; products with zero images still render a placeholder block.
- Annotated tag `v1.9.2` points at the release commit, not at the two later main commits (dark-mode rework, Beijing-time build metadata).
