# RiChangPIM v1.9.5 Version Log

Release date: 2026-10-24

## Release Scope

A UI-experience patch on top of v1.9.4. Three user-reported problems are fixed: the content workshop's DNA-source selector is renamed to 「创作 Skills」 so that a Skill (a writing method) is no longer confused with a DNA (where the method came from); the proposal creation dialog is re-laid out so item fields are no longer squeezed into a horizontal scroller; and the shared proposal page now shows only a summary table, with full product details (specification, material, colours, material notes, scene images) revealed in a dialog after a click. No database migration, no API contract change.

## Main Changes

- `frontend/src/views/ContentWorkshop.vue`: generation form field 「DNA 来源」 → 「创作 Skills」; options render the Skill name with its DNA shown as secondary text. Item cards keep the `source_dna_label` source line.
- `frontend/src/views/Proposals.vue`: creation dialog 640px → 920px, top-aligned labels, two-column rows (name/customer, customer archive/project), full-width item section.
- `frontend/src/components/ProposalItemEditor.vue`: new `compact` prop; item fields laid out in a two-column grid (quantity/remark, floor/space) with the material note spanning the full row; product picker and 「添加商品」 share one flex row; single column on ≤768px.
- `frontend/src/views/SharePage.vue`: summary-only tables plus a 「查看详情」 column; clicking a row opens a detail dialog with cover, number, category, location tags, specification, material, colours, material notes, prices, quantity, and a scene-image grid that opens the carousel at the clicked image.
- `frontend/src/components/ProductSceneCarousel.vue`: watches `initialIndex` so reopening the carousel lands on the selected scene image.

## Compatibility

- Application version: `1.9.5` (anchor `frontend/package.json`; `portal/package.json`, both lockfiles, `backend/app/core/config.py` `VERSION`, and the `docker-compose.yml` `APP_VERSION` fallback are all `1.9.5`).
- Database migration head: unchanged at `0030_content_dna_fields`. No new migration ships in this version.
- Backend code, API routes and permissions are unchanged; only frontend sources are touched, but the full stack is released at the same version per `版本控制规范和Git.md` §1.1.
- Existing PostgreSQL, Redis and MinIO volumes must be preserved; the update package contains no business data, objects or secrets.

## Upgrade Notes

1. Back up PostgreSQL (`pg_dump -Fc`) and confirm the MinIO backup state is `ok`.
2. `bash scripts/build_frontends.sh` (Node must be on `PATH`, e.g. `export PATH="/root/.nvm/versions/node/v24.18.0/bin:$PATH"`), then record `BUILD_ID` / `GIT_COMMIT` / `BUILD_TIME`.
3. Export `APP_VERSION=1.9.5`, `APP_ENV=production` and the recorded metadata, then `docker compose build backend nginx` and `docker compose up -d --no-deps backend nginx`.
4. Verify `alembic current` → `0030_content_dna_fields (head)`, `/api/v1/health`, `/api/v1/version`, and the 「系统管理 → 版本」 page (all four rows real, 「一致」).
5. Spot-check the three changed screens: content workshop 「创作 Skills」 selector, proposal creation dialog layout, shared proposal detail dialog.

## Known Risks

- When the content AI model is slow, `POST /api/v1/content/batches` times out at `CONTENT_AI_TIMEOUT` (180 s) and returns an error; the workshop shows the generic 「网络连接失败」 banner because the frontend interceptor maps non-2xx responses to that text. This is an AI-service latency issue, not a UI defect; raise `CONTENT_AI_TIMEOUT` or pick a faster model if it persists.
- The share API does not expose the per-item remark, so the detail dialog cannot show it; adding it would require a backend field in `_build_content`.
