# RiChangPIM v1.9.3 Version Log

Release date: 2026-10-12

## Release Scope

This release ships the CRM-Lite module set: the customer domain (CRUD, stage state machine, PII masking, dialogue/requirement/follow-up/solution sub-resources), the project domain (CRUD, membership, drawing assets .dwg/.dxf/.skp/.psd), the operations dashboard (5 endpoints with a cache layer), the content workshop (AI generation with compliance guard, publication registry, exposure entry, Excel import), and the reminder engine (R1/R1b/R2/R3/E1 rules, a dedicated worker, notifications). It adds 16 permission codes and the manager/designer/operator roles, 7 admin views with 3 shared components, and lazy-loaded echarts charts. The requirement spec `docs/10-客户项目与新媒体(CRM-Lite).md` originally targeted v1.10.0 (item A9); the release is unified at **v1.9.3** per the current-version decision, and `CHANGELOG.md` top section remains the single source of truth (`版本控制规范和Git.md` §1.1). The spec document is a historical decision record and was not rewritten.

## Main Changes

- Backend routers: `customers`, `projects`, `dashboard`, `content`, `reminders`; core modules `attachment_access`, `data_scope`, `masking`; services `content_service`, `content_state`, `customer_state`, `project_state`, `reminder_rules`; reminder worker `app.scripts.worker` (`docker-compose.worker.yml`).
- Migrations `0020_crm_perms` (16 permission codes + role seeds), `0021_content_tables`, `0022_reminders`; migration head advances `0017_operation_log_username` → `0022_reminders`. Customers/projects tables are created by the startup entrypoint (`Base.metadata.create_all`), not by a migration.
- Frontend: `Dashboard`, `Customers`, `CustomerDetail`, `Projects`, `ProjectDetail`, `ContentWorkshop`, `ContentPublications` views; `NotificationBell`, `TodoDrawer`, `EmptyMetric` components; new `crm.css`; echarts + vue-echarts (lazy-loaded). `PERMISSIONS` lock updated 57 → 73.
- Version unification at 1.9.3: `frontend/package.json`, `portal/package.json`, both lockfiles, `backend/app/core/config.py` `VERSION`, `docker-compose.yml` / `docker-compose.worker.yml` `APP_VERSION` defaults, `README.md` (current version + migration head), `AI-Docs/README.md`, `CHANGELOG.md`.
- Ops: `scripts/purge_operation_log.sh`; README-OPS "Worker 部署" section; `.env.example` gains `FEATURE_CRM` / `FEATURE_CONTENT` / `FEATURE_REMINDER`, `DASHBOARD_*`, `REMINDER_*`, `CONTENT_*`, `PII_VIEW_RATE_PER_HOUR` (all optional, with compose defaults).

## Compatibility

- Application version: `1.9.3` (anchor: `frontend/package.json`; compose fallback defaults also say 1.9.3 so a forgotten build arg no longer reports `dev`).
- Database migration head: `0022_reminders`; three forward-only migrations on top of `0017_operation_log_username`.
- Existing PostgreSQL, Redis, and MinIO volumes must be preserved; the cloud update package contains no business data, objects, or secrets.
- New environment variables are optional; compare `.env.example` before upgrading.

## Upgrade Notes

1. Back up PostgreSQL (`pg_dump -Fc`) and confirm MinIO backup state `ok` before replacing containers.
2. Build both frontends with `bash scripts/build_frontends.sh` and record `BUILD_ID` / `GIT_COMMIT` / `BUILD_TIME`.
3. Export `APP_VERSION=1.9.3` plus the recorded `BUILD_ID`, `GIT_COMMIT`, `BUILD_TIME`, `APP_ENV=production`; run `docker compose build backend nginx` (worker uses the same backend image).
4. `docker compose up -d --no-deps backend nginx`; deploy the reminder worker with `docker compose -f docker-compose.yml -f docker-compose.worker.yml up -d worker` (optional — reminders only fire with it).
5. Verify `alembic current` → `0022_reminders (head)`, `/api/v1/health`, `/api/v1/version`, the admin 「系统管理 → 版本」 page (four metadata rows real, check 「一致」), and the new CRM views (dashboard, customers, projects, content workshop, notifications).

## Gate Record (per 版本控制规范和Git.md §7)

- `scripts/gate.sh` on the release tree: backend ruff initially reported 7 `I001` import-sort errors → fixed with `ruff --fix` → clean; backend unit pytest passed; `vue-tsc --noEmit` passed; vitest — the permission-count lock `permissions.spec.ts` was updated 57 → 73 to match the 16 new CRM codes, file re-run 21/21 passed, all other suites passed in the same run; eslint passed; `vite build` passed.
- Not run this round: full backend `pytest` (DB/Redis/MinIO-dependent suites), Playwright e2e, and the browser version-page acceptance — these must pass on the target environment per `RELEASE_GATE.md` before the release is considered complete; the version-page check is part of cloud-side acceptance (§6.1).
- Known tooling issue discovered during this gate: `scripts/gate.sh` runs each check inside a subshell, so `run()` failures do not propagate to its exit code (it exits 0 despite `✗ FAIL` lines). Read the gate log output, not the exit code; fix candidate for a follow-up commit.

## Known Risks

- The echarts route chunk is ~1,020 kB minified (>1,000 kB build warning); it is lazy-loaded so only CRM dashboard routes pay the cost.
- Without the worker deployed (or with `FEATURE_REMINDER=false`), reminders do not fire; the rest of the system is unaffected.
- Content generation depends on the AI adapter configuration; `REMINDER_LLM_POLISH` defaults to `false`.
- The CRM spec doc (A9) still states target `v1.10.0`; this release ships as `v1.9.3` and the doc is intentionally not rewritten (historical record).
