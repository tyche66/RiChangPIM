# RiChangPIM AI 架构规划

本目录是独立的可插拔 AI 设计、规划、治理和扩展文档库。它与 `docs/` 当前业务工程文档并列维护，不作为过时文档归档；文档中的“目标”能力必须以代码和发布日志为准，不代表已经上线。

> 文档状态：已实施基线（Knowledge Gateway + AI Portal V1）后续增强见路线图  
> 编制日期：2026-07-29  
> 当前版本：v1.9.2
> 规划范围：AI 前台门户、Knowledge Gateway、知识检索、业务工具、模型接入、安全治理与运营体系  
> 目标容量：最多约 1 万产品、10 万知识块、数十名内部并发用户

## 1. 架构结论

RiChangPIM 的 AI 不建设为独立于 PIM 的第二套知识系统，而建设为 PIM 原生的智能交互与决策辅助层：

> **独立 AI 门户 + 后端内置 Knowledge Gateway + 受控业务工具 + PostgreSQL 混合 RAG + 异步索引 Worker + 可替换模型适配器。**

核心约束如下：

1. PostgreSQL 中的 PIM 业务表是产品、价格、库存状态、供应商、方案和报价的唯一真相源。
2. 说明书、规格书、证书等非结构化资料通过 RAG 提供证据，不替代业务字段查询。
3. 所有 AI 结果必须区分“数据库事实”“文档证据”“模型推断”，不得混为一谈。
4. 模型只能选择后端白名单工具，不能生成和执行任意 SQL，不能直接写业务表。
5. 权限在工具执行与知识召回前生效，不能依赖提示词隐藏敏感数据。
6. AI 可形成草稿和待确认动作；方案、报价、分享及数据修改必须由有权限的员工确认。
7. 首期不保存原始对话，但会话存储采用可插拔接口，预留后续受控启用完整历史。
8. 外部模型平台是可替换的推理供应商，不拥有 PIM 权限、文档状态或核心索引真相。

## 2. 已确认的老板决策

| 决策项 | 已确认结论 |
| --- | --- |
| 未来 6 个月场景 | 销售选型与方案、内部知识问答、数据治理助手、采购决策助手 |
| 门户用户 | 全体内部员工 |
| 外部数据源 | 首期以 PIM 当前数据为准，不虚构 ERP/CRM/WMS 实时性 |
| 模型策略 | 首期采用一个 OpenAI-compatible 服务，架构兼容多供应商 |
| 操作边界 | AI 生成草稿，人审后才能对外或改变业务状态 |
| 对话留存 | 暂不保存原始对话，预埋可配置存储接口 |
| 规划规模 | 最多约 1 万产品、10 万知识块 |

## 4. 文档使用规则

- 标记为“现状”的能力必须能在当前代码或部署文件中找到依据。
- 标记为“目标”的能力尚未实现，不得用于对外承诺或演示口径。
- 标记为“过渡”的能力只为降低迁移风险，必须给出退出条件。
- 需求变化先修改本目录中的决策和验收标准，再修改代码。
- AI 版本发布除遵循项目现有 `RELEASE_GATE.md` 外，还必须满足本规划新增的 AI 发布门禁。
