# P2 阶段任务提示词：知识生产化与 Portal MVP
## P2 总目标
你是 RiChangPIM AI Phase 2 的项目构建者/负责人。P1 已完成现有 FastAPI 内的统一只读 `Knowledge Gateway` 最小可运行切片。现在进入 **Phase 2：知识生产化与 Portal MVP**。
P2 的目标不是新增 AI 写动作，也不是做采购/销售闭环，而是把 P1 的只读智能层从“可调试、可插拔、可审计”推进到“知识生产化、可运营、可评测、可被内部 Portal 使用”的阶段：
- 建设独立 `portal/` 内部 AI 前台 MVP
- 建设生产化知识表：`knowledge_document`、`knowledge_chunk`、`knowledge_index_job`
- 建设索引 Worker/Dispatcher 基线
- 将现有 `LegacyRagRetriever` 替换/扩展为 `HybridRetriever`
- 支持精确召回、关键词召回、pgvector 语义召回、RRF 融合
- 完成来源定位、引用校验、删除/替换一致性
- 保持 P1 的只读边界：不执行业务写入、不实现 pending_action、不创建方案/报价/分享
- 修复 P1 遗留测试/环境问题，并补齐 P2 集成、权限、安全、E2E、评测门禁
- 旧 `/api/v1/ai/*` 和 P1 `/api/v1/knowledge/query` 必须兼容

# 任务 4：解析、切块与索引 Job 基线
## 角色
你是知识流水线负责人，负责 P2 的索引任务基线和 Worker。
## 目标
建设最小生产化 Worker/Dispatcher，用 PostgreSQL 任务表作为真相源，可选 Redis Streams 投递。P2 必须能异步处理知识索引任务，但不要求完整大规模调度能力。

- `backend/app/knowledge/indexing/chunker.py`
- `backend/app/knowledge/indexing/embedder.py`
- `backend/app/knowledge/indexing/status.py`

可能修改：
- `docker-compose.yml`
- `Dockerfile`
- `backend/app/core/config.py`
- `backend/.env.example`
## 需求
1. Job 状态机：
   - `pending`
   - `dispatched`
   - `processing`
   - `succeeded`
   - `failed`
   - `dead`
2. Job 操作：
   - `upsert`
   - `delete`
   - `reindex`
3. Worker 行为：
   - 获取 pending job。
   - 加锁并写 `locked_by/locked_at/heartbeat_at`。
   - 执行解析/切块/embedding/upsert。
   - 成功写 `succeeded/completed_at`。
   - 失败写 `error_code/error_message`，不保存原文。
   - 超过重试次数进入 `dead`。
   - 重复消费幂等。
4. Redis Streams：
   - P2 可先实现 PostgreSQL polling。
   - 如果实现 Redis Streams，Redis 不是真相源，PG job 仍是最终状态。
   - Redis 不可用不能破坏核心 PIM。
5. 切块：
   - 目标 300-600 tokens 起步。
   - 支持章节、页码、表格 metadata。
   - 不能固定只按 600 字符粗切作为最终 P2 实现。
   - 不可靠页码可为空，但必须标注低质量。
6. Embedding：
   - 通过既有 Adapter/Model Gateway。
   - `AI_ADAPTER=none` 时 job 失败或保持 pending/degraded，不能标成功。
   - 记录 embedding 模型、版本、维度。
## 验收
- 可通过命令启动 Worker。
- 创建 `knowledge_index_job` 后可被处理到终态。
- Worker 崩溃/重复处理不产生重复 chunk。
- `AI_ADAPTER=none` 时索引不伪装成功。
- 失败不删除旧成功索引。
- 单元测试覆盖状态机、幂等、失败重试、敏感日志。
- 集成测试覆盖一次完整 manual/product_card 索引流程。
