# Furnispace PLP 前端设计 Skill

> 来源：Furnispace Minimalist Furniture Store Product Listing UI 设计稿  
> 类型：高端家具电商 / Product Listing Page（PLP）  
> 核心风格：Swiss Clean、暖调极简、商品摄影优先  
> 说明：尺寸与色值依据提供的静态设计稿估算，实施时允许在相邻层级内微调。

## 1. Skill 目标

在商品数量较多的家具目录中，通过明确层级、克制的信息密度和稳定的网格节奏降低浏览压力，让用户能快速完成以下任务：

- 识别当前商品分类。
- 扫描商品图片、评分、名称和价格。
- 收藏商品或快速加入购物车。
- 在浏览商品的过程中建立对品牌服务与审美的信任。
- 从列表自然过渡到品牌内容和购买入口。

本风格适合家具、家居、灯具、生活方式和其他依赖高质量商品摄影的中高端电商。它不适合需要高密度参数对比、强促销标签或复杂多条件筛选的商品类型。

## 2. 核心设计原则

### 2.1 商品是视觉主角

- 页面背景保持纯白，商品卡使用接近白色的浅灰底。
- 商品图采用干净抠图或统一影棚背景，避免复杂环境干扰轮廓。
- 卡片不使用明显描边和重阴影，主要依靠背景色、间距和轻微圆角区分层级。
- 单张商品图应占卡片可视高度约 `60%–70%`，四周保留充足留白。

### 2.2 用空间建立层级

- 页面采用宽松的纵向节奏：导航、标题区、筛选区、商品网格、信任区和品牌横幅之间保持明显间隔。
- 只在操作相关的元素上使用容器感，例如筛选胶囊、商品卡和按钮。
- 避免把每个页面区块都包装成卡片。

### 2.3 克制但不空洞

- 黑、白、浅灰构成 UI 主色，暖棕色只由家具摄影和生活方式图片提供。
- 黄色只用于评分星标，形成一个小而稳定的功能性色彩信号。
- 大标题承担品牌气质，小字号负责具体信息，避免无意义的装饰文字。

### 2.4 操作贴近决策点

- 收藏按钮放在卡片右上角。
- 快速加购放在卡片右下角，与商品名称和价格处于同一信息区。
- 评分位于左上角，用户无需进入详情页即可完成初步判断。
- 图标操作保持轻量，不抢夺商品图的注意力。

## 3. 页面信息架构

```text
Header
├── Brand logo
├── Primary navigation
└── Search / Cart / Login

AI product search
├── Natural-language prompt
├── Suggested prompts / context actions
├── Voice input
└── Send action

Product intro
├── Section heading
├── Supporting copy
└── Category pills

Product grid
└── Product card × N
    ├── Rating
    ├── Favorite
    ├── Product image
    ├── Name
    ├── Price
    └── Quick add

Why choose us
├── Heading and supporting copy
├── Service benefit grid
└── Lifestyle image

Lifestyle CTA banner
├── Brand statement
├── Supporting copy
├── Shop Now CTA
└── Footer links / copyright
```

页面叙事顺序遵循：`自然语言描述需求 → AI 搜索或直接浏览商品 → 理解服务 → 感受生活方式 → 进入购买`。AI 是商品发现的增强入口，不能取代传统分类筛选。

## 4. 布局规范

### 4.1 页面容器

- 桌面端内容最大宽度建议为 `1200–1280px`。
- 页面左右安全边距建议为 `48–64px`。
- 设计稿主体被置于浅灰展示底中；真实站点不必保留外围灰框，页面本身应使用白色背景。
- 使用 `12` 列基础栅格，核心商品区可直接映射为 `3` 列。

```css
.page-shell {
  width: min(100% - 96px, 1280px);
  margin-inline: auto;
}
```

### 4.2 AI 输入区

- 位于导航与首个商品浏览内容之间；具体相邻标题、文案和业务命名由项目上下文决定，不在本 Skill 中硬编码。
- 收起态最大宽度建议为 `760–880px`，居中显示，并与后续主体内容保持同一视觉轴线。
- 页面中只显示一个输入组件。它由一个连续的白色表面承载文本、产品类型快捷按钮、辅助操作和发送按钮，不叠放第二个输入框。下文保留两种单输入框变体作为设计参考，实际页面选择其中一种。
- 输入组件默认高度建议 `96–120px`；文本区在上，单行控制区在下，但二者属于同一容器、同一焦点上下文和同一查询状态。
- 与参考图一致，采用白色表面、`20–28px` 圆角、浅灰描边和极轻阴影；不要使用紫蓝渐变或发光装饰。
- 输入区与后续商品浏览内容建议保留 `56–72px`，形成清楚但不割裂的层级。
- 聚焦时只加强描边与阴影，不改变整体尺寸，避免首屏抖动。
- 用户发送后，以输入组件自身的位置和轮廓为动画起点向四周扩展，白色表面连续蔓延并覆盖整个视口，随后进入 AI 答复页面。

### 4.3 商品网格

- 桌面：`3` 列。
- 平板：`2` 列。
- 手机：`1` 列；宽屏手机可在商品信息足够简短时采用 `2` 列。
- 列间距建议 `16–20px`，行间距建议 `16–20px`。
- 所有卡片保持相同宽高比，避免图片尺寸和标题长度造成网格跳动。

```css
.product-grid {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 20px 18px;
}

@media (max-width: 900px) {
  .product-grid { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}

@media (max-width: 560px) {
  .product-grid { grid-template-columns: 1fr; }
}
```

### 4.4 信任区

- 桌面端采用左右分栏，文本功能区与图片区约为 `1.05 : 1`。
- 左侧功能点使用 `2 × 2` 网格。
- 图片与左侧内容顶部对齐，圆角不超过 `8px`。
- 移动端顺序为标题、服务点、图片，避免图片打断信息理解。

### 4.5 CTA 与页脚

- 生活方式横幅跨越完整内容宽度，桌面端建议宽高比约 `2.2 : 1`。
- 文案垂直和水平居中，采用白字覆盖真实室内场景图。
- 使用轻度暗色遮罩保障文字对比度，避免强渐变或明显色块。
- 页脚可以叠放在横幅底部，但必须与主 CTA 保持充足距离，并在移动端改为正常文档流。

## 5. 视觉 Token

### 5.1 色彩

| Token | 建议值 | 用途 |
|---|---:|---|
| `--color-bg` | `#FFFFFF` | 页面背景 |
| `--color-surface` | `#F4F4F2` | 商品卡背景 |
| `--color-text` | `#111111` | 标题、主要文字、激活态 |
| `--color-text-muted` | `#77736F` | 描述、次要信息 |
| `--color-border` | `#D8D8D4` | 胶囊与弱分隔线 |
| `--color-rating` | `#F5C400` | 评分星标 |
| `--color-overlay` | `rgb(24 18 12 / 32%)` | CTA 图片遮罩 |
| `--color-action-soft` | `rgb(255 255 255 / 78%)` | 图片上的圆形快捷操作 |

不要把暖棕色铺满 UI。暖色应主要来自摄影，界面框架保持中性黑白灰。

### 5.2 字体

- 使用现代无衬线字体，例如 `Inter`、`Helvetica Neue`、`Arial`。
- 标题采用 `700–800`，正文采用 `400`，商品名和按钮采用 `500–600`。
- 字间距统一为 `0`。
- 主标题使用紧凑行高，但不要使用负字距模拟品牌感。

| 层级 | 桌面建议 | 行高 | 字重 |
|---|---:|---:|---:|
| 页面标题 | `36–42px` | `1.05–1.15` | `700–800` |
| 区块标题 | `34–40px` | `1.1` | `700–800` |
| CTA 标题 | `48–64px` | `1.08` | `700–800` |
| 商品名称 | `14–16px` | `1.3` | `500–600` |
| 正文 | `14–16px` | `1.5` | `400` |
| 辅助信息 | `12–14px` | `1.4` | `400–500` |

移动端标题应按固定断点降级，而不是使用与视口宽度连续绑定的字号。

### 5.3 圆角与阴影

- 商品卡：`6–8px`。
- 分类胶囊：完整胶囊形，可使用 `999px`。
- 圆形图标按钮：`50%`。
- 大横幅：`8px`。
- 默认不使用阴影；悬停时可加入极轻阴影 `0 8px 24px rgb(0 0 0 / 6%)`。

### 5.4 间距系统

使用 `4px` 基础倍数：`4, 8, 12, 16, 20, 24, 32, 48, 64, 96`。

- 导航高度：`72–88px`。
- 标题到描述：`12–16px`。
- 描述到分类筛选：`20–24px`。
- 筛选到商品网格：`72–96px`。
- 商品区到信任区：`96–128px`。
- 信任区到 CTA：`96–128px`。

## 6. 组件规范

### 6.1 Header

- Logo 左对齐，主导航居中，工具操作右对齐。
- 导航文字保持简洁，单项不设置胶囊背景。
- 搜索、购物袋使用线性图标；登录可使用文字。
- 图标按钮可视尺寸约 `20px`，点击热区不得小于 `40 × 40px`。
- 移动端折叠为 Logo、菜单按钮和购物袋；搜索进入菜单或独立覆盖层。

### 6.2 AI Product Search Composer

两种方案共享相同的输入、提交和全屏扩展逻辑，区别只在底部控制区的信息组织。它们是可选变体，不代表两个连续状态，也不能同时上下堆叠。

#### 变体 A：产品类型选择器

```text
┌──────────────────────────────────────────────────────────┐
│ Text input                                               │
│                                                          │
│ +  [Product type ▾]  Context actions      Mic      Send ↑  │
└──────────────────────────────────────────────────────────┘
```

- 适合产品类型较多、需要通过菜单查找类型的目录。
- 选择器只显示当前产品类型或通用类型提示，展开后展示完整产品类型列表。
- 选择类型后将关键词写入输入框，控件本身不承担筛选结果状态。

#### 变体 B：产品类型快捷胶囊

```text
┌──────────────────────────────────────────────────────────┐
│ Text input                                               │
│                                                          │
│ +  [Type chip] [Type chip] [More ›]      Mic      Send ↑  │
└──────────────────────────────────────────────────────────┘
```

- 适合核心产品类型数量少、希望用户一步预填的目录。
- 直接展示 `2–3` 个高频产品类型，其余类型通过 `More` 或末尾箭头进入菜单。
- 点击胶囊后将类型关键词写入输入框，并给胶囊提供轻量选中反馈；仍需用户点击发送才开始搜索。

#### 两种变体的共同规则

- 输入框支持多行自然语言；具体占位文案由项目内容规范决定，本 Skill 只规定信息层级和交互行为。
- 参考图中类似模型选择器的胶囊控件，在本项目中必须解释为“产品类型选择”，不得出现模型名称、版本或切换模型的含义。
- 点击产品类型按钮后，将对应类型关键词写入输入框，并允许继续编辑；再次选择其他类型时应替换已有类型词或按产品规则追加，不得直接触发搜索。
- 产品类型控件使用产品类型名称，不使用推荐动作或模型标签。
- 左侧 `+` 仅表示可选的上下文附件入口；若项目不支持图片或文件输入，应直接移除，不能保留无效按钮。
- 麦克风和发送使用熟悉图标，发送按钮采用品牌黑色；只有需要强调 AI 状态时才使用单一功能色。
- 空输入时发送按钮禁用；输入有效后启用。`Enter` 发送，`Shift + Enter` 换行。
- 提交后，原输入组件通过共享元素动画扩展为全屏 AI 搜索工作台。扩展过程中复用同一个组件实例和查询状态，不创建第二个输入框。

全屏态结构：

```text
AI Search Workspace
├── Close button at the top-right
├── Assistant summary and active constraints
├── Search progress or clarification question
├── Product result grid
│   └── Product card with reason-for-match
└── The same composer, centered and fixed at the bottom
```

- 全屏层使用白色背景并覆盖当前内容。右上角始终保留独立关闭按钮，使用 `X` 图标、至少 `44 × 44px` 点击区域和明确的可访问名称。
- 关闭按钮距离桌面视口顶部与右侧建议 `24–32px`；移动端使用安全区加 `16px`。它不能随结果内容滚动离开视口。
- 顶部显示原始查询和 AI 提炼出的条件标签，如 `Small space`、`Ivory`、`Under $300`；标签可单独移除。
- AI 输出先给一段不超过三行的搜索摘要，再展示商品结果，避免做成纯文本聊天页。
- 结果卡沿用原 PLP 卡片，额外增加一句简短匹配理由；价格、评分、收藏和快速加购继续可用。
- 原输入组件在全屏态重新定位为底部水平居中的固定控件，用于增量修改搜索；宽度沿用收起态约束，并设置 `width: min(880px, calc(100% - 32px))`。
- 输入组件底部距离桌面视口建议 `24–32px`；移动端放在底部安全区上方。结果滚动容器必须预留足够底部空间，避免最后一行商品被输入框遮挡。
- 任何状态下都不能同时出现顶部与底部两个输入框。
- 无结果时提供放宽条件、删除限制和回到完整目录的明确操作。

### 6.3 Category Pills

- 激活态：黑色背景、白色文字。
- 默认态：透明或白色背景、浅灰描边、深灰文字。
- 高度建议 `36–40px`，水平内边距 `18–22px`。
- 单行优先；移动端允许水平滚动，不要强制压缩文字。
- 切换分类后保持用户当前滚动上下文，显示轻量加载反馈。

### 6.4 Product Card

卡片是视觉容器，不应成为信息面板。固定结构如下：

```text
┌ Rating                         Favorite ┐
│                                        │
│             Product image              │
│                                        │
│ Product name                           │
│ Price                         Quick add │
└────────────────────────────────────────┘
```

- 建议宽高比为 `1 : 0.88–0.96`，所有卡片必须一致。
- 内边距建议 `18–20px`。
- 商品图使用 `object-fit: contain`，避免裁掉家具轮廓。
- 商品名最多显示两行；价格永远保留独立行或稳定基线。
- 收藏按钮默认无实心背景，悬停或聚焦时显示浅色圆形底。
- 快速加购使用白色圆形按钮，图标采用购物袋或加号购物车。
- 点击卡片主体进入详情；收藏和加购必须阻止卡片导航事件。

### 6.5 Rating

- 使用单个黄色星标加数值，避免在小卡片内铺满五颗星。
- 数值使用高对比度深色，字重 `500–600`。
- 评分缺失时隐藏整个区域，不显示 `0.0`。

### 6.6 Benefit Item

- 使用线性图标、短标题和最多两行说明。
- 图标独立存在，不放入装饰性彩色圆块。
- 文案围绕实际收益：快速送达、轻松购物、售后保障、灵活退换。
- 避免重复相同标题；设计稿中的重复文案在正式产品中应修正。

### 6.7 Lifestyle CTA

- 背景必须是可辨识的真实家具场景，不能只使用模糊氛围图。
- 标题使用直接的品牌主张，例如 `DESIGN THAT SPEAKS SIMPLICITY`。
- 正文控制在两行以内。
- CTA 使用浅色半透明按钮或实色按钮，保证在背景上稳定可见。
- 背景图必须设置合理焦点，移动端使用单独裁切图或 `object-position` 调整主体。

## 7. 交互与动效

静态设计稿未提供可验证的时间参数，以下为匹配该风格的建议：

- AI 展开：点击发送后，输入框白色表面从原位置在 `320–420ms` 内向四周扩展至整个视口；边界圆角逐渐归零，原页面内容同步淡出，完成后输入组件移动到底部居中位置并显示 AI 答复内容。
- AI 生成：先显示具体状态文案，如“正在匹配 126 件商品”，再渐进呈现摘要和首批结果；不要用无限循环的虚假打字效果拖延结果。
- AI 关闭：点击右上角关闭按钮或使用浏览器返回键时，执行展开动画的反向过程，并恢复原页面滚动位置、查询内容和筛选状态；按 `Escape` 也应触发相同行为。
- 分类切换：商品网格使用 `160–220ms` 的淡入与轻微上移，不做夸张重排动画。
- 卡片悬停：商品图放大到 `1.02–1.04`，卡片轻微上浮 `2px`。
- 收藏：心形描边到填充，持续 `140–180ms`，立即提供状态反馈。
- 快速加购：按钮显示短暂成功状态，同时更新购物袋数量。
- 所有动画使用 `ease-out` 或接近 `cubic-bezier(0.2, 0.8, 0.2, 1)` 的缓动。
- 尊重 `prefers-reduced-motion`，关闭位移和缩放，只保留必要的透明度变化。

## 8. 响应式策略

### Desktop：`≥ 1024px`

- 完整导航。
- AI 输入框保持 `760–880px` 居中宽度；全屏态结果区最大宽度与页面容器一致。
- 商品三列。
- 信任区左右分栏。
- CTA 大标题可使用两行居中布局。

### Tablet：`768–1023px`

- 导航可保留精简版本或折叠菜单。
- AI 输入框占据内容宽度；全屏结果为两列。
- 商品两列。
- 信任区保持分栏时缩减服务说明，也可以改为单列。
- 页面水平边距降至 `32px`。

### Mobile：`< 768px`

- 页面水平边距 `16–20px`。
- AI 输入框圆角降至 `16–20px`，产品类型胶囊可横向滚动；全屏态使用 `100dvh`，结果单列，唯一输入组件固定在安全区上方。
- 分类筛选横向滚动，并隐藏滚动条但保留触控滚动能力。
- 商品单列，宽屏手机可酌情两列。
- 信任区单列，服务点 `1` 列或紧凑 `2` 列。
- CTA 高度增加，标题缩至 `32–40px`，页脚离开图片叠层进入正常流。
- 触控目标最小 `44 × 44px`。

## 9. 可访问性与内容规则

- 正文和背景对比度至少满足 WCAG AA。
- 图标按钮必须提供可访问名称，如 `Add Verona Luxe Sofa to cart`。
- 收藏状态使用 `aria-pressed`，分类选择使用可表达选中状态的控件。
- 商品图片 `alt` 应描述商品名称与品类，不堆砌营销关键词。
- 焦点环必须清晰可见，不能仅靠颜色变化表示状态。
- 快速加购后使用非打断式状态提示，并通过 `aria-live` 通知辅助技术。
- AI 全屏层使用语义化 `dialog` 或独立路由；展开后焦点进入查询标题或结果区，关闭后焦点返回原输入框。
- 右上角关闭按钮的可访问名称使用项目语言表达“关闭 AI 搜索”；全屏态打开后应限制键盘焦点范围，`Escape` 关闭。
- AI 搜索进度通过 `aria-live="polite"` 播报，流式更新不要重复朗读整段回答。
- 上传房间图片前说明用途；不要在未经授权时长期保存图片或从图片推断敏感属性。
- 不要用占位文案重复填充服务区；每个利益点必须表达不同价值。

## 10. 实现建议

建议组件拆分：

```text
ProductListingPage
├── SiteHeader
├── AIProductSearch
│   ├── AIComposer
│   └── AISearchWorkspace
│       ├── ActiveConstraints
│       ├── SearchSummary
│       └── AIResultGrid
├── ProductIntro
├── CategoryFilter
├── ProductGrid
│   └── ProductCard
├── BenefitsSection
│   └── BenefitItem
├── LifestyleBanner
└── SiteFooter
```

商品数据应保持结构化：

```ts
type Product = {
  id: string;
  name: string;
  category: 'sofa' | 'chair' | 'table' | 'bed' | 'lamp';
  price: number;
  currency: string;
  rating?: number;
  image: string;
  imageAlt: string;
  isFavorite: boolean;
};
```

- AI 搜索使用独立状态机：`idle → composing → expanding → searching → streaming → results | clarification | empty | error`。
- 将查询条件保存为结构化对象，而不是只保存聊天文本；商品检索结果必须来自产品库，AI 层只负责理解意图、排序解释和追问。
- AI 全屏态建议映射到可恢复 URL，如 `/products/ai?q=...`，确保刷新、返回和分享行为可靠。
- 搜索请求支持取消和重新提交；流式响应必须防止旧请求覆盖新结果。
- 使用 CSS Grid 构建商品列表，避免用固定宽度和手工换行。
- 为商品图片预留固定 `aspect-ratio`，避免图片加载造成布局位移。
- 商品图片使用响应式资源和延迟加载，但首屏图片应优先加载。
- 筛选状态同步到 URL 查询参数，支持返回、刷新和分享。
- 快速加购要处理加载、成功、失败和库存不足状态。

## 11. Do / Don't

### Do

- 把 AI 定位为“找到合适商品”的工具，并让结果立即可购买。
- 在 AI 摘要中明确显示被理解的预算、尺寸、风格和材质条件。
- 让摄影承担暖色与氛围，UI 保持中性。
- 使用稳定栅格、统一卡片比例和明确纵向间距。
- 把评分、收藏和加购放在用户视线最容易扫描的位置。
- 在商品列表之后安排服务证据和生活方式内容。
- 保持图标风格、线宽和点击热区一致。

### Don't

- 不要让全屏态变成只有大段文字的通用聊天机器人。
- 不要伪造库存、价格、评分或商品匹配结果；所有事实必须来自产品数据。
- 不要在输入框周围加入高饱和渐变、光晕和与家具品牌无关的科技感装饰。
- 不要加入重阴影、玻璃拟态、彩色渐变或大面积暖棕 UI。
- 不要在商品卡上堆叠促销、库存、配送、规格等全部信息。
- 不要把每个区块做成悬浮卡片，也不要出现卡片嵌套。
- 不要让不同尺寸的商品图改变卡片高度。
- 不要用大幅缩放、弹跳和长时间视差破坏安静的品牌感。
- 不要为了极简而隐藏必要的价格、状态反馈和可访问标签。

## 12. 验收清单

- [ ] AI 输入组件位于导航与首个商品浏览内容之间，且没有绑定特定标题文案。
- [ ] 页面与全屏态始终只有一个输入组件，不出现双输入框或重复查询状态。
- [ ] 产品类型选择器与快捷胶囊作为两种备选方案被保留，但实际界面只启用其中一种。
- [ ] 产品类型胶囊不显示模型信息；点击后只预填或更新输入框中的产品类型关键词。
- [ ] 用户可输入自然语言并通过按钮或键盘提交，空输入不可提交。
- [ ] 提交后输入框连续扩展为全屏工作台，不出现明显布局闪烁。
- [ ] 全屏 AI 页面右上角始终有固定关闭按钮，并支持点击、键盘聚焦和 `Escape`。
- [ ] 全屏后复用的输入组件固定在页面底部水平居中，且不遮挡最后一项搜索结果。
- [ ] AI 结果包含搜索摘要、可编辑条件和真实商品卡，而非只有聊天文本。
- [ ] 关闭或返回后恢复 PLP 的滚动位置、分类和查询草稿。
- [ ] 加载、澄清、无结果、错误和取消状态均有完整界面。
- [ ] 首屏能在 3 秒内识别页面主题、分类入口和商品列表。
- [ ] 桌面商品网格为稳定三列，平板两列，手机单列或合理双列。
- [ ] 商品图完整可见，不变形、不裁切关键轮廓。
- [ ] 每张卡片都能查看评分、名称、价格、收藏和快速加购。
- [ ] 所有卡片高度一致，图片加载时无明显布局跳动。
- [ ] 分类激活态清晰，切换后状态可被键盘和辅助技术识别。
- [ ] 信任区的四个利益点内容互不重复。
- [ ] CTA 文案在所有背景裁切和断点下保持可读。
- [ ] 手机端无横向页面溢出，分类胶囊可独立横向滚动。
- [ ] 所有图标按钮都有工具提示或可访问名称。
- [ ] 动效克制，并兼容 `prefers-reduced-motion`。
- [ ] 页面色彩仍以黑、白、中性灰为主，暖色由商品和场景图提供。

## 13. 一句话调用描述

> 为高端家具电商构建 Swiss Clean 风格的响应式商品列表页：在导航与商品浏览内容之间设置单一自然语言搜索组件，其中胶囊控件用于预填产品类型而非选择模型；提交后复用同一组件并以共享元素动画扩展为全屏搜索工作台，输出带匹配理由的真实商品结果，同时维持克制的中性界面、清晰商品网格和直接购买路径。
